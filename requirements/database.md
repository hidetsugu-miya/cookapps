# Database requirements

## D-1 Database screen and connections

The sidebar has a button for the database screen (`#nav-database`, `aria-label` "データベース"), after Orca and before the bottom group. Its icon is a drawn cylinder (a line icon like the other buttons, not text; the owner's instruction, 2026-11-14), and it has no count.

The screen (`#database`) has two parts, as the Slack screen has (S-19, `#slack-screen`): the side menu at the left (`#database-side`, the `--bar` background) and the work pane at the right (`#database-pane`), with a divider (`#database-side-split`) that the user drags (`ts/split.ts`, `--side-w`, 15 to 40% of the screen, 20% at first, kept in memory only). The side menu has a header of the height of every header (A-23, `#database-side-head`, a place to drag the window by) with the title "接続" and the plus (`#database-add`, `.icon-btn`, `aria-label` "接続を追加"), and under it the list (`#database-side-feed`). The work pane has a header (`#database-header`, a place to drag the window by) with the title "データベース" and, under it, `#database-work`, which holds the tables of the database that was pressed last (D-3); the tabs of records, structure and SQL are added in it later. The screen shows no placeholder and no text that explains a field or a button, and nothing is drawn for an empty list.

The list is what `database_profiles` answers (the connections in the order they were made, each with `passwordSaved`), read each time the screen is shown and again after every save and every delete, so the list is the same after the app is opened again and is never kept apart from the file. A read that fails shows its error on the error line (`#error`). A row (`.database-item`) is a button (`.database-btn`: a cylinder icon and the name, cut with an ellipsis) and the button of its menu (`.icon-btn.database-more`, three dots, `aria-label` "{name} のメニュー"), a sibling of the first. Pressing a row makes it the selected one (`aria-pressed` true; one at a time, in memory only, dropped when the connection is gone from the list) and opens the connection (D-3). The menu (`menu.ts`) has "編集", "切断" while the connection is open (D-3) and, in the danger color, "削除". The list is drawn again only when what it shows changes, and the focus stays.

The plus and "編集" open the popup (`#database-form`, `role="dialog"`, in the middle of a dimmed screen; the screen behind is inert while it is open, so Tab stays inside; the title is "接続を追加" or "接続を編集"). Its fields, with their names above (no placeholder), are the ones of the profile of Rust (`DatabaseProfile`): 接続名, ユーザー名, パスワード (a password field; for a connection whose password is saved, a status label "保存済み" with a dot beside the name, and the field empty: the password is never sent to the screen), the checkbox "SSM 経由で接続する", and, only while it is checked, "AWS のプロファイル名", "リージョン" and "踏み台の名前", then "DB のホスト" and "ポート" (a number field, 3306 for a new connection). The first field has the focus. "保存" sends `database_profile_save` with `profile` (the `id` empty for a new connection, else the connection's own, and the fields as typed; a port that is empty or not a number is sent as 0, which Rust refuses in Japanese) and `password` (the field as typed, empty to keep the saved one); the checks are Rust's, and the screen sends the fields as they are, also those of a hidden group. On success the popup closes and the list is read again. A refusal shows its text in `#database-form-error` (`role="alert"`) under the fields, and the popup stays with what was typed, so that "保存" can be pressed again (it is off while the call is on its way). "キャンセル" and Escape (unless it only cancels an IME conversion) close it and call nothing; a press on the dimmed part does not, so that typed text is not lost by accident. Leaving the screen closes it.

"削除" opens the confirmation of `confirmDelete` (`ts/hint.ts`, `role="alertdialog"`: "削除しますか？", "{name} を完全に削除します。元に戻せません。", a red "削除" and "キャンセル", which has the keys) under the button of the row's menu. "削除" calls `database_profile_delete` with the `id`, and the list is read again, also when the call failed, with its error on the error line; "キャンセル", Escape and a press elsewhere call nothing.

The unit tests (`cargo test`, `database.rs`) cover the file, the checks and the password. The E2E spec `database.e2e.ts` covers the button (the label and the icon, no text), the two parts, the list in the order given and read again at each showing, the error of a failed read, the press that selects (what it opens is D-3's), the popup (the fields, the group that the checkbox shows, the focus, no placeholder), a save of a new connection and of an edit (the arguments of `database_profile_save`, the list read again), the port sent as 0, the refusal shown with the popup kept, the saved password shown as a status, キャンセル and Escape, and the confirmation, the delete (`database_profile_delete` and the list read again), its failure and the selection of a connection that is gone.

## D-2 Connection to MySQL and the test of a connection

The server is MySQL 5.7, 8.0 or 8.4, and the login is `mysql_native_password` or `caching_sha2_password`. A session is opened by one function (`database/mysql.rs`, `connect`), which the connection test and the screens that come after it (tables, records, SQL) all use. It connects to `127.0.0.1` and the local port of the tunnel when the connection goes through SSM (D-1, `database/ssm.rs`), and to the DB host and the port of the connection when it does not. TLS is used when the server offers it, and the password of `caching_sha2_password` goes through it (a server with no TLS that asks for it is the error 「このユーザーの認証 (caching_sha2_password) には TLS が要りますが、サーバーが TLS を使えません」). The session is made read only at once (`SET SESSION TRANSACTION READ ONLY`), so that MySQL itself refuses a write. A connection has 15 seconds, from the first byte to the answer of the first query.

The popup of D-1 has a button "接続をテスト" (a `.text-btn`, between "保存" and "キャンセル", `type` "button", so that Enter in a field still saves). It tests the connection as typed in the popup, not as saved: it sends `database_test` with `profile` (the fields as typed, as "保存" sends them) and `password` (the field as typed). Rust takes the password typed, and when the field is empty the one saved in the keychain for `profile.id` (none for a new connection, which logs in with no password). The fields go through the same checks as a save (all but the name's being another connection's), and a refusal is the error. A connection that uses SSM opens its tunnel first, then logs in, runs `SELECT VERSION()` and closes the session, and the tunnel is closed whatever the result was; a tunnel that cannot be closed after a test that passed is told as the error 「MySQL {version} に接続できましたが、トンネルを閉じられませんでした: …」, because its session is left at AWS.

The answer is shown in `#database-test-result` (`role="status"`), under the port and above the error line of the save, and nowhere else: a success is a status with a dot, "MySQL {version}" (the version as `SELECT VERSION()` answers it, such as "MySQL 8.0.36"), and an error is its text in the danger color, as Rust words it. It is hidden while a test is on its way and the button is off, so that two tests do not run at once; the button is on again when the answer is shown. A test saves nothing and does not close the popup. A popup closed while a test is on its way draws nothing when the answer comes (the tunnel is closed in Rust all the same), and a popup opened again shows no answer.

The errors are told apart, and each is worded for the person who has to act:
- The tunnel is open and MySQL does not answer (the connection is closed or reset with nothing said, a time out, a refusal on the local port): 「トンネルは開きましたが、MySQL が応えません。踏み台から DB のホストとポートに届くか（DB のセキュリティグループが踏み台からの接続を許しているか）を確かめてください」. It is never worded as a login that failed.
- MySQL refuses the user name or the password (1044, 1045, 1698): 「MySQL へのログインに失敗しました。ユーザー名とパスワードを確かめてください: {the server's message}」. The message holds no password.
- MySQL does not let the client's host in (1129, 1130), any other error of the server (its number and message), and an error of TLS or of the protocol, each with its own words.
- Without a tunnel, the same failures name `{host}:{port}`: nothing answers, a refusal of the connection, a time out.
- The errors of the tunnel itself (an AWS login that is gone, a bastion that is not found, no `session-manager-plugin`, a time out) are those of D-1's `database/ssm.rs`, and they stop the test before MySQL is tried.

The unit tests (`cargo test`, `database/mysql.rs` and `database.rs`) cover what each error of the server, of the socket and of the protocol is, the words of each (the tunnel and the direct cases, the cut of a long message), the choice of the password and of the endpoint, the outcome of a test with a tunnel that cannot be closed, and, against a MySQL server of a few lines on a local `TcpListener`, a server that closes the connection, one that says nothing (the time out), one that refuses the login (1045), a port that refuses, and that a session sends `SET SESSION TRANSACTION READ ONLY`. The E2E spec `database.e2e.ts` covers the button (its place and that it calls nothing before it is pressed), the arguments of `database_test` for a new connection and for an edit (the id, the fields as typed now, the typed or the empty password), the version shown as a status, the error shown as it is, that the popup stays and nothing is saved, the button off and the old answer hidden while the test is on its way, and a popup closed meanwhile.

## D-3 Open a connection, and the databases and tables under it

A press on a connection row opens it: the screen calls `database_connect` with the `id` and the row opens, with its databases under it (`.database-btn` rows of depth 1, keyed `{id}/d/{name}`, in the order of the server). A press on a database row opens it: the screen calls `database_tables` with the `id` and the `database`, and the tables of the database are under it (rows of depth 2, keyed `{id}/d/{name}/t/{table}`, by name; a view is among them). A row that can open has a chevron and `aria-expanded`; a press on one that is open closes it (nothing is called, and a connection that is closed in the tree stays connected), and a press on a closed one opens it and reads again, so that what is shown is never older than the press. A press selects the row (`aria-pressed`), a table row too, which calls nothing: the work pane keeps the table list, and the tabs of the table come in it with #633 to #635. A press on a row whose read is on its way, or on a connection whose disconnect is on its way, does nothing but select it.

Rust keeps what a connection opened (`database/session.rs`, `Sessions`, managed by Tauri): one read only session for each connection (D-2, `database_connect` opens the tunnel when the connection uses SSM, logs in with the saved password, and reads the databases), used again by every read until it is closed. `database_connect` on a connection that is open reads only. The session is closed (and its tunnel, which stops the plugin and ends the SSM session) by "切断", by a save of that connection (its session was made with what is saved no more), by its delete, by a query that shows the stream broken (the connection is then closed and the screen is told so), and by the app's exit (the sessions, then the tunnels, `lib.rs`). A connection whose databases cannot be read is closed again. `database_connections` answers the ids that are open, which the screen reads after a save, a delete and a failed read of tables, to close the trees that Rust closed. A tunnel that cannot be closed after a save or a delete is told in the error (「接続は保存しましたが、トンネルを閉じられませんでした: …」), because its session is left at AWS. A connection that was deleted while it opened is closed when it has opened.

The databases are read from `information_schema.SCHEMATA` (every one the user may see, the system ones too) and the tables from `information_schema.TABLES` with the name of the database bound as a value, never put in the SQL text. Each query has 30 seconds; one that is past it closes the connection (the stream is in an unknown state). The error is one of D-2's words for the connection, 「MySQL がエラーを返しました ({number}): …」 for an error of the server, 「MySQL との接続が切れました。もう一度開いてください: …」 for a broken stream, and 「接続が開いていません。もう一度開いてください」 for a read after the close.

The dot (`.database-dot`, at the right end of the connection row, `role="img"`, `data-state`): green and the label "接続済み" while the connection is open (`connected`), orange and "接続しています" while it opens (`connecting`), gray and "未接続" otherwise (`closed`). The row's menu has "切断" between "編集" and "削除" only while the connection is open. "切断" calls `database_disconnect` with the `id`, and the tree of the connection closes at once, the dot goes gray, and the connection is selected; its work pane empties when it showed one of its databases; a failure shows its error on the error line (`#error`) and the tree stays closed, and a press on the connection waits until the call has answered.

The loading and the failures are drawn in the tree and in the work pane, with no other text on the screen:
- While a connection opens, a line "接続中…" (`.database-note`, `role="status"`) is under its row and the dot is orange; while its databases are read again, the line is "読み込み中…". While a database's tables are read, the line "読み込み中…" is under its row and in the work pane.
- A failure is its text in the danger color (`.database-note.danger`, `role="alert"`) under the row that failed: a connection that could not be opened (the dot is gray and nothing is under it), a database whose tables could not be read (the connection stays open; the text is also in the work pane). The row stays open, and a press on it reads again. A read that shows the connection lost closes the tree of the connection and the text is under the connection, with the dot gray.

The work pane (`#database-work`) has, for the database pressed last (also when its row is closed again), its name (`h3`) and the table list (`table.database-tables`) with the columns 名前, 行数（概算）, サイズ and エンジン, a row for each table in the order of the tree. The row count is the estimate of `TABLE_ROWS` with thousands separators; the size is `DATA_LENGTH` plus `INDEX_LENGTH` as "512 B" or with one decimal in KB, MB, GB or TB (1024 each); the engine is `ENGINE`; Rust words the three (`format_rows`, `format_size`), and they are empty for a view. The row of the table pressed in the tree has `aria-selected` true. A database with no table draws its name only. Nothing is drawn when no database was pressed, or when the connection of it was closed.

Not tried against a real server by this code (only the pure parts and a local fake of the protocol, `cargo test`): the result of the two queries (the types of `information_schema` columns on MySQL 5.7, 8.0 and 8.4), which are cast in the SQL (`CAST … AS CHAR` and `AS UNSIGNED`) so that they decode as text and as unsigned numbers.

The unit tests (`cargo test`, `database/session.rs`, `database/mysql.rs` and `database.rs`) cover the rows with separators, the size in each unit (the edges 1023 B, 1.0 KB, a value that rounds to 1024 of a unit, TB), the size of data and index together and empty, the row of a table and of a view, that the database is a bound value, the reads and the close of a connection that is not open, which error is a lost session (a broken stream, the protocol) and which is not, the words of each, the saved login of an id (the profile and the password, none, a connection that is gone), and the words of a tunnel that cannot be closed. The E2E spec `database.e2e.ts` covers the open of a connection (the call and its argument, the databases in order, the dot), 接続中… and the orange dot while it opens, a press meanwhile, the error of a connection and the open again, the close and the open again of a connection (a read each time), the open of a database (the call and its arguments, the tables under it, the table list with its columns), 読み込み中… in the tree and in the pane, the error of a read of tables (in both, the connection kept, the open again), a connection shown lost, the close of a database and the pane that stays, a table pressed (marked, nothing called), a database with no table, the menu with and without "切断", the disconnect (the call, the tree closed, the dot, the pane, the open again) and its failure, a save and a delete of an open connection, and a connection deleted while it opens.
