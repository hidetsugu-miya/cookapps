# プライバシーポリシー

最終更新日: 2026年11月16日

つなぎAI（以下「本アプリ」）は、利用者自身のパソコン（macOS または Windows）上で動くデスクトップ Gmail クライアントです。
本アプリが Google アカウントのデータをどう扱うかを説明します。

## 取得するデータ

本アプリは、利用者の同意を得て、Gmail API と Google Calendar API から次のデータを取得します。

- 受信トレイのスレッドの一覧（差出人、件名、日時、抜粋、既読状態）
- 利用者が開いたスレッドのメッセージ本文
- ログインした各アカウントのメールアドレス
- 受信トレイを最新に保つための、メールボックスの変更履歴（history）。約 10 秒ごとに確認します
- 利用者のカレンダーの一覧（各アカウントのすべてのカレンダーの ID、名前、色、自分が持ち主かどうか、Google 側の表示設定）
- 表示中の週の予定（タイトル、開始・終了の日時、利用者自身の出欠の状態、場所、説明、Meet のリンク、参加者の人数と承諾した人数、カレンダーの名前）。参加者の名前とメールアドレスは取得しません。カレンダーを開いたとき、週を移したとき、表示中は 5 分ごとに取得します
- Claude との連携（`tsunagiai-mcp`）を利用者が設定した場合は、MCP クライアントからの呼び出しに応じて、上と同じ種類のデータを取得します。予定は、呼び出しで指定された期間のものを取得します
- Claude との連携（`tsunagiai-mcp`）を利用者が設定した場合は、MCP クライアントからの呼び出しに応じて、上と同じ種類のデータを取得します。予定は、呼び出しで指定された期間のものを取得します

要求するスコープは次の 2 つです。

- `https://www.googleapis.com/auth/gmail.modify`
- `https://www.googleapis.com/auth/calendar.readonly`（予定を閲覧するためだけに使い、予定の作成・編集・削除はしません）

利用者が Todoist に接続した場合は、Todoist のサーバーから、タスク（名前、説明、期限、優先度、サブタスク、ラベル）とプロジェクトとラベルも取得します。
アプリを起動したとき、Todo 画面を開いたとき、ウィンドウに戻ったとき、約 10 秒ごと（前回からの変更だけ）、タスクを操作したあとに取得します。
サイドメニューの Todo に、期限の時刻を過ぎたタスクの件数を表示するためです。
タスクの詳細を開いたときは、そのタスクのコメント（投稿者、日時、本文、添付ファイルの名前と URL）も取得します。
投稿者の名前を調べるため、Todoist の自分のユーザー情報と、自分以外の人が書いたコメントがあるときはそのプロジェクトの共同編集者の一覧も取得します。

## データの使い方

取得したデータは、本アプリの画面に表示するためだけに使います。
例外は、利用者が「Todo にする」を押したスレッドの件名と、アカウントのメールアドレスを含む Gmail の URL を Todoist に送ることと、利用者がコメントの送信を押したときにそのコメントの文章と選んだファイルを Todoist に送ることです。
約 10 秒ごとに変更履歴を確認し、変わったスレッドの一覧用の情報（差出人、件名、日時、抜粋、既読状態）だけを取り直して画面に反映します。
利用者の操作に応じて、スレッドのゴミ箱への移動と、受信トレイからの除外（アーカイブ）を Gmail API に依頼します。
利用者が「元に戻す」を押したときは、その取り消し（ゴミ箱からの復元、受信トレイへの戻し）も依頼します。
また、スレッドの既読・未読の切り替えも Gmail API に依頼します。
未読のスレッドを開いたときも、既読にするよう依頼します。
利用者がスレッドの返信欄か新規作成の画面で「送信」を押したとき（返信欄では ⌘Enter でも）は、書いたメール（宛先、Cc、Bcc、件名、本文）の送信を Gmail API（`users.messages.send`）に依頼します。
返信のときは、同じスレッドに入るように、そのスレッドの最後のメッセージの Message-ID と References を Gmail API から読み、送るメールに付けます。
送信には上のスコープ `gmail.modify` を使い、新しいスコープは求めません。
入力しただけでは送りません。
カレンダーの予定は、画面に表示するためだけに使います。
`tsunagiai-mcp` を設定した場合は、取得したデータを、利用者が設定した MCP クライアント（Claude Code など）へ渡します。
スレッドのゴミ箱への移動、アーカイブ、既読・未読の切り替えも、そのクライアントからの呼び出しに応じて Gmail API に依頼します。
メールの削除（ゴミ箱を経由しない削除）と、設定の変更はしません。
`tsunagiai-mcp` は、メールを送信しません。

## 保存

ログインの維持に使うリフレッシュトークンは、アカウントごとに OS の資格情報の保管場所（macOS ではキーチェーン、Windows では資格情報マネージャー）へ保存します。
ログインしたアカウントのメールアドレスの一覧は、本アプリの設定フォルダに保存します。
「画像を表示」を押した送信者のメールアドレスの一覧も、設定フォルダに保存します。
起動直後や画面を開いた直後に、取得を待たずに前回の内容を表示するため、表示した週のカレンダーの予定（最大 10 週。場所や説明などの詳細を含みます）を設定フォルダのファイルに保存します。
カレンダーは、すべてのアカウントとカレンダーを取得できた週だけ、新しい内容に書き換えます。
アカウントを削除すると、このファイルも消えます。
受信トレイのスレッドの一覧は保存しません。以前の版が保存したファイルは、受信トレイを読み込んだときに消します。
カレンダーの週の始まりの曜日の設定も、設定フォルダに保存します。
表示するカレンダーの選択（カレンダーの ID と、表示するかどうか）も、設定フォルダの `calendar-selection.json` に保存します。アカウントを削除すると、そのアカウントの分が消えます。
開発の画面のエディタの自動保存までの時間の設定も、設定フォルダの `editor-settings.json` に保存します（時間の数値だけです）。
画面ごとの書体と大きさの設定も、設定フォルダの `font-settings.json` に保存します（書体の名前と大きさの数値だけです）。
データベースの画面の接続（接続名、ユーザー名、事前スクリプト、DB のホスト、ポート）は、設定フォルダの `database-profiles.json` に保存します。パスワードはこのファイルには入れず、OS の資格情報の保管場所に接続ごとに保存します。
データベースの画面の右ペインの Claude タブで Claude Code を起動するたびに、設定フォルダの `claude-code/` に、起動のスクリプト（`start.sh` か `start-with-tools.sh`）と MCP の設定（`mcp.json`）を書きます。中身は本アプリが決めたパスと決まった引数だけで、メール、Slack のメッセージ、Todo は入れません。
開発の画面のオーケストレーションで作ったフォーメーションは、設定フォルダの `formations/{フォーメーションの名前}/` に、作った時刻と、選んだプロジェクト（環境の名前とリポジトリの名前）を `formation.json` として保存します。フォーメーションを削除すると、このフォルダごと消します。
開発の画面のリーダーの Claude Code を起動するたびに、そのフォーメーションのフォルダ（`formations/{フォーメーションの名前}/`）に、リーダーへの指示（`CLAUDE.md`）、MCP の設定（`mcp.json`）、起動のスクリプト、空のプロジェクト設定（`.claude/settings.json`）を書きます。中身は本アプリが決めた文、パス、決まった引数だけで、メール、Slack のメッセージ、Todo は入れません。
保存した環境（Orca に保存した接続先）の PC に `tsunagiai-mcp` を置くことに同意すると、設定フォルダの `formation-remote.json` に、環境の名前ごとに、その PC のサーバーの公開鍵と版を保存します（これが同意の記録です）。本アプリの秘密の鍵は、このファイルではなく、OS の資格情報の保管場所（サービス `jp.mysis.tsunagiai.formation`）に保存します。同意を取り消すと、その環境の分を消します。
リーダーがチームメイトを予定に入れるか起動すると、`tsunagiai-mcp` が、チームメイトの名前、環境の名前、リポジトリの名前と、起動したチームメイトでは worktree の場所、ブランチ、Orca のターミナルの識別子、起動した時刻を、そのフォーメーションのフォルダの `children.json` に保存し、チームメイトを終えるとそのチームメイトの分を消します。チームメイトへの指示の文は保存しません。
リーダーがこの Mac のリポジトリでチームメイトを起動すると、`tsunagiai-mcp` は、そのリポジトリの git のフォルダの `info/exclude` に `/.claude/worktrees/` の 1 行を、まだ無ければ足します（チームメイトの worktree を `git status` に出さないためです。`.gitignore` は変えません）。
設定の「スキル」タブで作ったスキル（名前、表示名、使う画面、説明、指示）は、設定フォルダの `claude-plugin/skills/{名前}/SKILL.md` に保存します。「削除」を押すと消えます。
アプリのログは、設定フォルダの `app-log.jsonl` に保存します（時刻、重さ、場所、500 文字までの短い内容。30 日より古い行は消し、ファイルは 1 MiB までにします）。トークン、メール、Slack のメッセージ、Todo、ターミナルの出力は書きません。いまの版には、ログに書き込む機能はまだありません。
Todoist に接続している場合は、同じ目的と、取得に失敗したときの表示のために、Todoist のタスクとプロジェクトとラベルを設定フォルダのファイルに保存します。
Todoist の接続を解除すると、このファイルも消えます。
メールの本文は保存せず、本アプリを終了すると消えます（`tsunagiai-mcp` も同じです。`tsunagiai-mcp` が書き換えるのは、データベースの接続を保存するツールが呼ばれたときの `database-profiles.json` と、そのときに消すことのある接続のパスワードと、リーダーのツールが呼ばれたときの `formations/{フォーメーションの名前}/children.json` と、上のリポジトリの `info/exclude` と、サーバーとして動かしたとき（下の「保存した環境の PC に置く `tsunagiai-mcp`」）の `remote/` の中と、本アプリに頼まれてチームメイトの記録から消す名前だけです）。
返信欄と新規作成の画面に書いた内容（宛先、件名、本文）も保存しません。

HTML 形式のメールに含まれる画像は、既定では読み込みません。
利用者がメッセージの「画像を表示」を押したときだけ、そのメッセージの画像を送り主のサーバーから取得します（https のみ）。
このとき、そのメッセージの送信者のメールアドレスを覚え、以後はその送信者のメッセージを開いたときに、画像を自動で取得します。
覚えた送信者を外す画面はありません。外すには、アプリを終了してから、設定フォルダの `image_senders.json` からそのメールアドレスを消してください。
自動で取得するのは、Gmail が付けた認証結果（Authentication-Results）が DMARC 合格、または From のドメインと一致する DKIM 署名の合格のメッセージだけです。
そうでないメッセージは、覚えた送信者のものでも、「画像を表示」を押すまで取得しません。
このとき、取得先のサーバーに利用者の IP アドレスが伝わり、メールが開かれたことが送り主に知られることがあります。
スタイルシートなど、画像以外の外部のものは読み込みません。
メール本文のリンク（http と https のみ）は、利用者が押したときだけ、既定のブラウザで開きます。
本アプリ自身はそのリンクの先と通信しません。

## Todoist との連携

利用者が Todoist の個人 API トークンを入力した場合に限り、本アプリは Todoist のサーバーと通信して、タスクとプロジェクトを表示・操作します。
「Todo にする」を押したスレッドの件名と、アカウントのメールアドレスを含む Gmail の URL を Todoist に送り、トークンは OS の資格情報の保管場所に保存して、設定画面の「Todoist の接続を解除」で消せます。
取得したタスクとプロジェクトとラベルは、起動直後や Todo 画面を開いた直後と、Todoist に接続できないときに前回の内容を表示するため、設定フォルダに保存し、接続を解除すると消します。
コメントは保存せず、本アプリを終了すると消えます。
コメントの文章と、利用者が選んだファイルは、利用者がコメントの送信を押したときだけ Todoist に送ります。入力しただけ、ファイルを選んだだけでは送りません。

## Slack との連携

利用者が Slack の User OAuth Token を設定に入力した場合に限り、本アプリは Slack のサーバー（slack.com）と通信します。
トークンはワークスペースごとにいくつでも入力でき、入力したときに Slack の `auth.test` で確かめ、設定画面を開いたときにも確かめます。
「Slack に貼る」を開くと、選んだワークスペースの参加しているチャンネルの名前を Slack から取得し、本アプリを閉じるまでメモリにだけ覚えます。
「Slack に貼る」の画面で Claude に依頼を送ったときは、貼り先の候補にするため、つないでいる各ワークスペースの参加しているチャンネルの名前を同じように取得します（覚えてから 10 分たっていなければ、覚えたものを使います）。
依頼に Slack のリンクを貼ったときは、その先を貼り先の候補にするため、リンクのチャンネルの名前を、そのワークスペースのトークンで Slack から取得します（`conversations.info`。つないでいるワークスペースのリンクだけで、1 回の依頼で 5 件まで）。
Slack のリンクを入力したときは、そのチャンネルの名前を Slack から取得します。
トークンは OS の資格情報の保管場所にワークスペースごとに保存し、設定画面の「接続を解除」で、そのワークスペースのトークンを Slack に取り消して消せます。画面には表示しません。
メールの内容を Slack に送るのは、利用者がメールの詳細画面で開いた「Slack に貼る」の画面で「投稿」を押したときと、その画面で投稿を頼む依頼を Claude に送ったときだけです。
Claude への依頼で投稿するのは、本アプリが、依頼そのものに投稿を頼む言葉があり、どの投稿の貼り先も、利用者の選んだ貼り付け先、依頼で名指ししたチャンネル、依頼に貼った Slack のリンクの先、同じ並びの前の投稿のスレッドのどれかで、どの文面にも、元の文章にも依頼にも無いリンクやメンションが無いと確かめたときだけで、投稿するかを Claude には決めさせません。1 件でも外れたら、何も投稿しません。
送るのは、「Slack に貼る」の画面の「元のメッセージ」と、「行うこと」のカードに書いた文面（利用者が書いたもの、または利用者の依頼で Claude が書いたもの。1 回の投稿につき 10,000 文字まで）です。「行うこと」のカード 1 枚が 1 回の投稿で、「投稿」を押すと、まだ投稿していないカードを上から順に送ります。
編集欄には、初めにスレッドの最新のメッセージの件名、差出人、日時、本文のテキスト（3,000 文字まで）が入り、利用者が自由に直せます。送る内容は、利用者が編集した文章です。
編集欄の文章、宛先、Claude との会話は、本アプリを終了するまでメモリにだけ残り、保存しません。
ワークスペースの ID、名前、ユーザー名、URL は、設定フォルダの `slack-workspaces.json` に保存します。
貼れた宛先（ワークスペースの ID、チャンネル ID、チャンネル名、スレッドの識別子）は、新しい順に 8 件まで、同じ場所の `slack-recent.json` に保存します。メールの内容は保存しません。
送ったメッセージは、利用者の Slack ワークスペースと Slack のポリシーに従って扱われます。

### Slack のリアルタイム更新（App-Level Token）

利用者が設定の「Slack」タブの「リアルタイム更新」で App-Level Token（`xapp-` で始まる）をワークスペースごとに登録した場合に限り、本アプリは Slack の Socket Mode の WebSocket（`slack.com` のサブドメインの `wss` のアドレス。`apps.connections.open` で Slack が毎回知らせるもの）を開き、本アプリを起動している間はつなぎ続けます。切れたときは、間隔をのばしながら自動でつなぎ直し、つなぎ直したときは一覧を読み直します。
この接続で Slack から届くのは、トークンを取ったアプリの Event Subscriptions で利用者が選んだ、パブリックとプライベートのチャンネルのメッセージのイベント（投稿、スレッドの返信、編集、削除）です。本アプリはイベントを受け取ったことを Slack に返すだけで、イベントの中身は保存せず、どのチャンネル（とスレッド）が変わったかを知るためだけに使います。DM とグループ DM のイベントと、そのほかのイベントは、返信して捨てます。
イベントがあったチャンネルは、そのつど、上の「Slack の一覧とスレッド」と同じ呼び出し（`conversations.history`、スレッドの返信は `conversations.replies`、まだ知らない名前は `users.info`）で Slack から読み直し、メモリにだけ置きます。同じチャンネルのイベントは 1 秒ごとにまとめ、同じチャンネルを読み直すのは 10 秒に 1 回まで、1 つのワークスペースでは 1 分に 20 回の呼び出しまでにします（超えた分は、あとでまとめて読みます）。一覧に出さないチャンネルのイベントは捨て、読みません。
App-Level Token は、OS の資格情報の保管場所にワークスペースごとに保存し、画面にもログにも出しません。Slack に拒否されたら、消します。

### Slack の一覧とスレッド

本アプリは、起動したときと、ウィンドウが見えている間の 1〜2 分ごとに（Slack の画面を開いていないときも。サイドメニューの Slack のアイコンに未読の数を出すためです。App-Level Token を登録して、すべてのワークスペースがつながっている間は 5 分ごとです）、トークンのユーザーが参加しているパブリックとプライベートのチャンネル（DM とグループ DM は除く）のメッセージ、スレッドの返信、ユーザーの名前とアイコンを、Slack から読みます。
読んだメッセージの本文、ブロックと添付のカードの文字、名前、アイコンの URL、添付ファイルの名前は、本アプリを終了するまでメモリにだけ置き、保存しません。
ユーザーの名前は 1 時間、メモリに覚えます。
送信者と自分のアイコンは、Slack の画像サーバー（`slack-edge.com` とそのサブドメイン）と Gravatar（`secure.gravatar.com`）から、トークンを付けずに取得します。Slack が別のホストのアイコンの URL を返したときは取得せず、名前の頭文字を出します。取得した画像は、本アプリを終了するまでメモリにだけ置きます。
スレッドの詳細を開いたときは、添付された画像のサムネイルを `files.slack.com` から、トークンを付けて取得し、本アプリを終了するか、そのワークスペースを削除するまで、メールの画像とは別のメモリにだけ置きます（保存しません）。トークンは、`files.slack.com` 以外へは送りません。
アイコンとサムネイルの取得のために、利用者の IP アドレスが、その画像サーバーに知られます。
ボットやアプリの投稿は、ブロックや添付のカードに画像を入れることがあります。
その画像は、既定では読み込みません。
利用者がスレッドの詳細のメッセージの「画像を表示」を押したときだけ、そのメッセージの画像を、画像の URL のサーバーから取得します（https のみ）。
そのサーバーは Slack 以外の任意のサーバーで、利用者の IP アドレスが伝わります。
Slack のトークンは付けません。トークンが要る Slack の画像（`files.slack.com`）は取得しません。
取得した画像は、メールの画像と同じメモリに、本アプリを終了するまでだけ置き、保存しません。
返信の文章を Slack に送るのは、利用者がスレッドの詳細の返信欄で矢印か ⌘Enter を押したときだけです（10,000 文字まで）。入力しただけでは送りません。返信の文章は、本アプリを終了するまでメモリにだけ残り、保存しません。
返信の文章とスレッドのメッセージを Anthropic に送るのは、利用者がスレッドの詳細の Claude 欄で依頼を書いて送信を押したときだけです。送るのは、返信欄の文章（空のこともあります）、開いているスレッドのメッセージ、それまでの会話、今回の依頼です。
スレッドのメッセージは、送信者の名前、日時、画面に出ている本文で、ボットの投稿のブロックと添付の文字、ボタンと添付のリンクの URL も含みます（Claude が返信案でリンクを扱えるようにするためです）。長いスレッドは、新しいメッセージを優先して合わせて 10,000 文字までにし、古いものを省きます。読めたのがスレッドの途中までのときは、その旨も添えます。
Claude Code を通じて Anthropic のサーバーへ送られます。会話は、本アプリを終了するまでメモリにだけ残ります。
Slack の画面の Claude のペインで、利用者が依頼を書いて送信を押したときだけ、本アプリは同じように Claude Code を起動します。送るのは、それまでの会話と今回の依頼で、チャンネルの履歴を出しているときは、そのチャンネルの名前と、履歴に出ているメッセージ（送信者の名前、日時、本文。新しいメッセージを優先して合わせて 10,000 文字まで）も送ります。「未読」と「ウォッチ」から送ったときは、Slack のメッセージは送りません。
Claude Code を通じて Anthropic のサーバーへ送られます。Claude が返した下書きは、利用者が「投稿欄に入れる」を押したときにチャンネルの投稿欄に入るだけで、Slack には送りません。会話と下書きは、本アプリを終了するまでメモリにだけ残ります。
一覧とスレッドの読み出しには、トークンのスコープ `channels:history`・`groups:history`・`channels:read`・`groups:read` が要ります。名前とアイコンには `users:read`、添付画像には `files:read`、ユーザーグループへのメンションの名前には `usergroups:read` を使い、なければその分だけ出ません（メンションは「@不明」と出ます）。
スレッドの詳細またはチャンネルの履歴にリアクションのあるメッセージを読んだとき、またはリアクションの絵文字のピッカーを開いたときは、ワークスペース独自の絵文字の名前と画像の URL を `emoji.list` で Slack から読みます（`emoji:read` が要り、なければ読まず、リアクションは `:name:` で出ます）。名前と URL は、本アプリを終了するか、そのワークスペースを削除するまで、メモリにだけ 1 時間置き、保存しません。読めなかったときは 5 分後に読み直します。
独自の絵文字の画像は、アイコンと同じく、Slack の画像サーバー（`slack-edge.com` とそのサブドメイン）と Gravatar だけから、トークンを付けずに取得します。別のホストの URL は取得しません。取得した画像は、アイコンと同じく、本アプリを終了するまでメモリにだけ置き、保存しません。
リアクションを付けた人のユーザー ID は、読んだメッセージに付いていますが、自分が付けたかどうかを判定するためだけに使い、画面には出さず、メモリにだけ置いて保存しません。自分のユーザー ID は、ワークスペースごとに `auth.test` で一度読み、メモリにだけ置きます。
利用者がリアクションを押したとき、またはピッカーで絵文字を選んだときだけ、そのメッセージのチャンネルの ID とメッセージの `ts` と絵文字の名前を、`reactions.add`（付けるとき）または `reactions.remove`（外すとき）で、利用者自身の名前で Slack に送ります（`reactions:write` が要り、なければ送らず、通知に理由を出します）。押さなければ、送りません。ピッカーの「最近」は、このアプリを開いている間に付けた絵文字の名前を、ワークスペースごとに 24 個まで、メモリにだけ置き、保存しません。
ユーザーグループへのメンションを名前で出すために、ワークスペースごとにユーザーグループの ID とハンドルを `usergroups.list` で読みます（無効にしたグループも含みます）。ID とハンドルは、本アプリを終了するか、そのワークスペースを削除するまで、メモリにだけ置き、保存しません。1 時間ごとに読み直し、失敗したときは 5 分後に読み直します。
また、一覧の未読と既読を分けるために、メッセージを保持しているチャンネル（1 回の読みにつき 1 ワークスペースで最大 40 件）の既読位置（Slack の `last_read`）を、`conversations.info` で読みます。既読位置は、本アプリを終了するか、そのワークスペースを削除するまで、メモリにだけ置き、保存しません。
一覧のメッセージを開くと、そのチャンネルの既読位置をそのメッセージまで進めるよう、`conversations.mark` で Slack に送ります（すでに既読のメッセージを開いても送りません）。これには `channels:write`（公開チャンネル）と `groups:write`（非公開チャンネル）が要り、なければ送らず、未読の表示も変えません。この 2 つのスコープは、Slack の仕様で、チャンネルの管理権限も含みますが、本アプリは既読位置を送る `conversations.mark` にしか使いません。足さなくても、既読を Slack と同期すること以外は使えます。
利用者がサイドメニューのチャンネルを押したときは、そのチャンネルの最新の 50 件のメッセージを `conversations.history` で Slack から読み、履歴として出します（呼び出すのはそのチャンネル 1 件だけです。ユーザーの名前とアイコンは、上と同じように読みます）。読んだメッセージは、本アプリを終了するまでメモリにだけ置き、保存しません。履歴を開いても、既読位置は送りません。
チャンネルの履歴の下の欄の文章を Slack に送るのは、利用者が欄の矢印か ⌘Enter を押したときだけです。`chat.postMessage` で、そのチャンネルへ、利用者自身の名前で、編集した文章を Slack の書き方に直して投稿します（10,000 文字まで。`chat:write` が要ります）。スレッドの返信欄の文章も、同じように直して送ります。入力しただけでは送りません。文章は、本アプリを終了するまでメモリにだけ、チャンネルごとに残り、保存しません。
チャンネルの見出しの「既読にする」を押したときは、一覧に出ていない分も含め、本アプリが持っているそのチャンネルの最新の未読のメッセージまで既読位置を進めるよう、`conversations.mark` で Slack に送ります。上の 2 つのスコープのないワークスペースには送りません。
利用者がサイドメニューのボタンで「一覧に出さない」を選んだチャンネルは、ワークスペースの ID とチャンネルの ID だけを、設定フォルダの `slack-hidden.json` に保存します（メッセージの本文や名前は保存しません）。そのチャンネルは、メッセージも既読位置も Slack から読みません。ただし、そのチャンネルでウォッチしているスレッドは、外すまで読みます。設定の Slack タブで戻すか、そのワークスペースを削除すると、消えます。Slack 側のミュートは読まず、変えません。
利用者が一覧の行のしおりで「ウォッチ」を選んだスレッドは、ワークスペースの ID、チャンネルの ID、スレッドの `ts`、最後に開いたときの最新の返信の `ts` だけを、設定フォルダの `slack-watched.json` に保存します（メッセージの本文、名前、アイコンは保存せず、本アプリを終了するまでメモリにだけ置きます）。ウォッチしたときと、一覧を読み込むたびに（確かめたのが古いものから 20 件まで）、そのスレッドの先頭のページを `conversations.replies` で Slack から読み、最初のメッセージと新しい返信の数を出します。呼び出し制限に当たったら、そのワークスペースのその回は打ち切り、Slack が示す時間が過ぎるまで確かめません。外すか、そのワークスペースを削除すると、消えます。
一覧には、未読の返信のあるスレッドも出します。そのために、一覧を読み込むたびに、本アプリが持っている返信のあるメッセージのスレッドの先頭のページを `conversations.replies` で Slack から読みます（確かめる順に、全ワークスペースで 1 回 20 件まで。呼び出し制限の扱いはウォッチと同じです）。本文、名前、アイコンは、本アプリを終了するまでメモリにだけ置きます。
Slack にはスレッドの既読位置を書き込む公開の API がないので、本アプリでスレッドを読んでも、Slack 側のスレッドの未読は消えません。本アプリで読んだ位置は、ワークスペースの ID、チャンネルの ID、スレッドの `ts`、読んだ最新の返信の `ts` だけを、設定フォルダの `slack-thread-seen.json` に保存します（新しいものから 500 件まで。メッセージの本文や名前は保存しません）。そのワークスペースを削除すると、消えます。

## データベースとの連携

データベースの画面は、利用者が登録した MySQL のサーバーに、利用者が接続を開いたときと「接続をテスト」を押したとき（`tsunagiai-mcp` では `db_test` が呼ばれたとき）だけつなぎます。
登録しただけ、画面を開いただけではつなぎません。
ユーザー名とパスワードは、そのサーバーへのログインに使います。パスワードは画面には出さず、ログとエラーの文にも出しません。
サーバーが TLS を使えるときは TLS でつなぎます。この Mac 以外のホストへの接続では、事前スクリプトの有無によらず、TLS が使えないサーバーにはつながず、パスワードを平文で送りません。どちらの場合も、サーバーの証明書は確かめません。
データベース、テーブル、列の名前と、利用者が開いたテーブルのレコード（1 ページ 100 行。長い文字列は 200 文字まで）と、利用者が「実行」を押した SQL の文とその結果（先頭の 1,000 行まで）は、MySQL のサーバーから読み、画面に出すだけです。
「実行」を押した SQL の文が書き込みの文（INSERT、UPDATE、DELETE など）のときは、接続のユーザーの権限でそのまま MySQL のサーバーで実行し、すぐに確定します。本アプリが自分で書き込むことはありません。
読んだ内容と書いた SQL の文は、本アプリを終了するまでメモリにだけ置き、保存せず、ログにも出しません。
Anthropic など、MySQL のサーバー以外へは送りません。
接続は、利用者が「切断」を押すか、接続を編集・削除するか、本アプリを終了するまで開いたままにします。
接続を削除すると、設定フォルダの `database-profiles.json` のその接続と、資格情報の保管場所のそのパスワードを消します。

### 事前スクリプト

接続に「事前スクリプト」を書いたときだけ、本アプリは、接続を開くときと「接続をテスト」のとき（`tsunagiai-mcp` の `db_test` のときも）に、そのスクリプトをこの Mac で子プロセスとして動かします。
スクリプトは利用者が書いたもので、本アプリは、前後の空白を除き改行を LF にそろえるほかは、中身を変えません。AWS Systems Manager のポートフォワードなど、スクリプトが何と通信するかは、スクリプトによります。
本アプリがスクリプトに渡すのは、接続に登録したポートの番号（環境変数 `TSUNAGIAI_PORT`。改名の前の名前の `COOKAPPS_PORT` にも同じ値を入れます）だけで、ほかの環境変数は本アプリのものを引き継ぎます。パスワードは渡しません。
本アプリは、スクリプトを動かす前に、接続のホストとポートに何かが応えないかを確かめ、応えるときはスクリプトを動かさずに失敗とします。スクリプトを動かしたあとは、接続のホストとポートで MySQL にログインします。
スクリプトの本文は、動かす間だけ、システムの一時フォルダの専用のフォルダにファイルとして書き、スクリプトが終わると、そのフォルダごと消します。
スクリプトの標準エラーの最後の 5 行（1 行 300 文字まで）は、失敗の理由として画面に出すだけで、保存しません（`db_test` では、呼び出した MCP クライアントへ返します）。
スクリプトは、接続を閉じるとき（「接続をテスト」のあとも）と本アプリの終了のときに止めます。本アプリが強制終了されたときは、スクリプトが動き続けることがあります。

### Claude Code からの接続の準備（`tsunagiai-mcp`）

利用者が `tsunagiai-mcp` を設定した場合は、MCP クライアントの呼び出しに応じて、次のことをします。

- `db_profiles`: 保存した接続（接続名、ユーザー名、事前スクリプト、DB のホスト、ポートと、パスワードを保存しているかどうか）をクライアントへ返します。パスワードは返しません。
- `db_profile_save`: クライアントが渡した接続を `database-profiles.json` に保存します。ユーザー名、事前スクリプト、ホスト、ポートを変えたときは、事前スクリプトの有無によらず、その接続の保存したパスワードを消します。パスワードを保存することはありません。
- `db_test`: 保存した接続を、保存したパスワードでテストし、MySQL の版か、失敗の理由（スクリプトの標準エラーの最後の行を含みます）をクライアントへ返します。データベースの中身は読みません。

### データベースの画面の Claude タブ

利用者がデータベースの画面の右ペインを開いたとき（作業ペインと接続の編集ペインの、どちらの見出しのアイコンからでも）、Claude Code が動いていなければ、本アプリはこの Mac の Claude Code（`claude`）を、設定フォルダの `claude-code/` で、右ペインの先頭の Claude タブに起動します。
Claude Code に渡す MCP サーバーは `tsunagiai-mcp` だけで、サインインは設定の「Claude」タブで選んだ方式（サブスクリプションか API キー）を使います。
Claude タブに打ち込んだ内容と、Claude Code が呼んだツールの結果は、Claude Code を通じて Anthropic のサーバーへ送られます。このタブの Claude Code は、Bash などの組み込みの道具も使えます。
書き込むツールとコマンドは、使う前に Claude Code が利用者に確かめます。
タブに出た内容と打ち込んだ内容を、本アプリは保存しません。Claude Code 自身が会話をどう保存するかは、Claude Code の扱いに従います。
Claude Code は、Claude タブの × を押したときと、本アプリを終了したときに止めます。Claude Code が自分で終わったときも止まります。右ペインを閉じても、データベースの画面を離れても、編集ペインを閉じても止めません。

利用者が開発の画面の言語サーバーの欄で、見出しの ✦ か言語のカードの「Claude に頼む」を押したとき、本アプリはこの Mac の Claude Code（`claude`）を、設定フォルダの `claude-code/` で、欄のカードの下のペインに起動します。
Claude Code に渡す MCP サーバーは `tsunagiai-mcp` だけで、サインインは設定の「Claude」タブで選んだ方式を使います。
最初の指示として、Orca の環境の名前、プロジェクトの ID、worktree のパス（保存した環境の worktree では、ssh の接続先の名前も）を渡します。
ペインに打ち込んだ内容と、Claude Code が呼んだツールの結果は、Claude Code を通じて Anthropic のサーバーへ送られます。このペインの Claude Code は、Bash などの組み込みの道具も使えます。
書き込むツールとコマンドは、使う前に Claude Code が利用者に確かめます。
ペインに出た内容と打ち込んだ内容を、本アプリは保存しません。Claude Code 自身が会話をどう保存するかは、Claude Code の扱いに従います。
Claude Code は、ペインの ✕ を押したとき、Orca の一覧から worktree が消えたとき、本アプリを終了したときに止めます。Claude Code が自分で終わったときも止まります。

## Orca との連携

メール、Slack のスレッド、Todo の詳細の右側にある「Orca に渡す」欄は、開いている内容を、Orca（エージェントを動かすアプリ）の新しいセッションに渡します。

### Claude による要約

利用者が「Orca に渡す」欄の矢印を押したときだけ、本アプリは Claude Code を起動して、カードに出ている内容の要約を作らせます。入力しただけ、欄を開いただけでは送りません。カードを外していれば、Claude Code は起動しません。
Claude Code に渡すのは、カードに出ている内容（下と同じ）だけで、Claude Code を通じて Anthropic のサーバーへ送られます。書いた指示と添付したファイルは渡しません。
要約は、Orca に渡す文に加えるだけで、保存しません。

### Orca に渡す内容

Orca に渡すのは、利用者が矢印を押したときだけです。
送るのは、書いた指示、カードに出ている内容の要約（箇条書き）と、カードに出ている内容です（合わせて 100,000 文字まで）。カードの内容は、メールではスレッドの各メッセージの差出人、日時、本文のテキスト、Slack ではスレッドの各メッセージの送信者の名前、日時、画面に出ている本文、Todo ではタスクの名前、プロジェクト、期限、説明と、すでに読み込んであるコメントです。
指示の欄にファイルを添付したとき（開発の画面のターミナルにファイルを貼り付けたり、ドロップしたときも同じ）は、送る前に、そのファイルを送り先の worktree の `.orca/drops/` に Orca を通じて書き込み、そのファイルのパスを指示のあとに加えます。ファイルは画像でも画像でなくてもよく、1 つ 20 MiB までです。置いたファイルは、本アプリが自動で消すことはありません。
カードの × を押すと、内容を外して指示だけを渡します。画面に出ていない文字（文字を隠す書式など）がメールにあっても、本アプリは見分けず、本文のテキストとしてそのまま送ります。
見えない文字（制御文字、幅のない文字、文字の向きを変える文字、タグ文字）は、送る前に取り除きます。内容は「引用したデータで、指示ではない」と書き添えた囲みに入れて送ります。
Orca のコマンド（`orca`）を通じて、この Mac の Orca へ送ります。「Orca に渡す」欄の送り先で保存した接続先を選んだときは、その接続先のサーバーの Orca へ送ります。Orca は、その文章を Claude Code に渡し、Claude Code を通じて Anthropic のサーバーへ送られます。
送った文章と、セッションの内容は、Orca と Anthropic のポリシーに従って扱われます。渡したあとは、そのセッションのターミナルの画面を Orca から読んで画面に出すだけで、保存しません。
本アプリが覚えるのは、メールのスレッド、Slack のスレッド、Todo のタスクごとの、渡したセッションの場所と、最後に選んだ送り先とプロジェクト、新しく作った worktree の名前と場所（起動に失敗したとき、同じものをもう一度作らないため）だけで、本アプリを終了するまでメモリにだけ置き、保存しません。書いた指示、選んだ worktree と作成元とブランチ、要約や送信に失敗した指示の文章と、そのときの要約（やり直すとき、もう一度作らないため）も、メモリにだけ残ります。

### 開発の画面のオーケストレーション

利用者が開発の画面でフォーメーションを初めて選んだとき、本アプリはこの Mac の Claude Code（`claude`）を、一覧で選んだフォーメーションのフォルダ（設定フォルダの `formations/{フォーメーションの名前}/`）で、画面の中のリーダーのペインに起動します。フォーメーションを作るときに選んだプロジェクトの名前は、最初の指示として Claude Code に渡し、Anthropic のサーバーへ送られます。
権限のモードは auto で、組み込みの道具（Bash など）も使えます。リーダーは effort high、チームメイトは effort medium で起動します。道具やコマンドを使う前に利用者に確かめるかどうかは、Claude Code の auto モードが決めます。
Claude Code に渡す MCP サーバーは `tsunagiai-mcp` だけで、渡すツールは、環境ごとのリポジトリを読む・チームメイトを予定に入れる・起動する・終えるツールと、読み取りのツール（受信トレイの一覧、スレッド、予定の一覧、データベースの接続の一覧）だけです。サインインは設定の「Claude」タブで選んだ方式を使います。
リーダーに打ち込んだ内容と、Claude Code が呼んだツールの結果（メールの本文や予定を読んだときは、その内容）は、Claude Code を通じて Anthropic のサーバーへ送られます。
リーダーが環境の一覧を読むと、`tsunagiai-mcp` は、Orca のコマンド（`orca`）で、保存した接続先の一覧と、この Mac と各接続先の Orca のリポジトリの一覧を読みます。
フォーメーションを作る窓を開くと、本アプリは Orca のコマンドで、保存した接続先の一覧と、この Mac と各接続先の Orca のリポジトリの一覧を読みます。
フォーメーションを作ると、本アプリは Orca のコマンドで、選んだプロジェクトのリポジトリごとに、Orca の worktree の場所の設定を `.claude/worktrees` にします（すでにそうなっているリポジトリには書きません）。Orca のほかの設定は変えません。
リーダーがチームメイトを起動すると、この Mac のリポジトリでは `git rev-parse` で、そのブランチが `origin` にあるかと git のフォルダの場所を、`git symbolic-ref` で既定のブランチ（`origin/HEAD`）を読み（リモートとは通信しません）、`tsunagiai-mcp` は、そのリポジトリの Orca の worktree の場所が `.claude/worktrees` でなければ、Orca のコマンドでそう設定してから、Orca のコマンド（`orca`）で、指定した環境（この Mac か保存した接続先）の Orca に、指定したリポジトリに新しい worktree とターミナルを作り、そこで Claude Code を auto モードで起動して、リーダーが書いた最初の指示を送ります。チームメイトの Claude Code は Orca が動かし、チームメイトに送った指示とチームメイトのセッションの内容は、Orca と Anthropic のポリシーに従って扱われます。
チームメイトを終えるときは、`tsunagiai-mcp` が、この Mac のチームメイトではその worktree で `git status`、`git remote`、`git rev-list` をこの Mac で動かし、保存した接続先のチームメイトではその接続先の Orca に worktree の git の状態を問い合わせ、コミットしていない変更、追跡していないファイル、どのリモートにも無いコミットが無いときだけ、Orca を通じてチームメイトのターミナルを閉じ、worktree をブランチごと消します。git のコマンドは、リモートとは通信しません。
流れのペインでチームメイトのカードから「削除」を押したときと、完了したチームメイトのタブかカードの × を押したときも、本アプリが同じように確かめて閉じます。閉じられないときは、変更のあるファイルと追跡していないファイルの名前、どのリモートにも無いコミットの 1 行目を、git（保存した接続先のチームメイトは、その接続先の Orca）から読んで画面に出します（保存しません）。そこで利用者が「強制削除」を押したときだけ、git の状態を確かめずに、Orca を通じてその worktree を強制で消します（変更と追跡していないファイルは失われます。どのリモートにも無いコミットのあるブランチは、Orca がローカルに残します）。
画面は、開発の画面を出している間、フォーメーションを選んでいるときは 3 秒ごとに、選んでいないときは 10 秒ごとに、フォーメーションの一覧とその `children.json` を読み、起動したチームメイトがあるときは、チームメイトごとの環境（この Mac か保存した接続先）の Orca の worktree とエージェントの状態（チームメイトの最後の返事を含みます）を読みます。リーダーが入力待ちかを知るために、この Mac のリーダーでは、Claude Code が端末に書くタイトルを、リーダーの出力から読み、保存した接続先のリーダーでは、その接続先の Orca の端末の一覧からタイトルを読みます。中のペインのタブで選んだチームメイトのターミナルの画面を、Orca から読んで写すか、開発の画面がストリームで見せている保存した接続先のチームメイトでは、開発の画面と同じくストリームで受け（ペインの大きさを Orca に伝えます）、打ち込んだキーを Orca を通じてそのチームメイトに送ります。読んだ状態と画面は、本アプリを終了するまでメモリにだけ置き、保存しません。
フォーメーションを削除するときは、チームメイトをすべて上と同じように確かめてから、リーダーの Claude Code を止め、チームメイトを終え、フォーメーションのフォルダを消します。閉じられないチームメイトがいるときは、何もせずにそのチームメイトごとに上と同じものを画面に出し、利用者が「強制削除」を押したときだけ、出したチームメイトの worktree を強制で消してから削除します。
リーダーの Claude Code は、本アプリを終了したときに止めます。Claude Code が自分で終わったときも止まります。モードや画面を離れても止めません。

### 保存した環境の PC に置く `tsunagiai-mcp`

保存した環境（Orca に保存した接続先）のフォーメーションでは、チームメイトの記録（`children.json`）がその PC の設定フォルダにあります。Orca のファイルの読み出しは、Orca に登録したフォルダの中しか読めないので、本アプリは、その PC に `tsunagiai-mcp` を置き、サーバーとして動かして、記録を読みます。
置くのは、利用者が同意したときだけです。その PC のプロジェクトでフォーメーションを初めて作るとき（同意の前に作ったフォーメーションでは、そのリーダーを起動するとき）に、置くものを示して聞きます。同意は PC ごとで、設定の Orca タブの「サーバーを置いた PC」から取り消せます。この Mac のフォーメーションには、置きません。
置くときは、その PC の Orca のターミナルで、本アプリと同じ版の `tsunagiai-mcp` を、GitHub の Release（`tsunagiai.app.tar.gz`）から、その PC がダウンロードします。`tsunagiai-mcp` だけを取り出し、署名があること、その署名が本アプリの署名と同じ Team ID のものであることを確かめてから、その PC の設定フォルダの `remote/` に置きます。署名の確認に通らなければ、何も置きません。リリースしていない開発版と、署名のない本アプリは置けません。macOS（Apple Silicon）の PC だけに置けます。
`remote/` には、プログラム、版、サーバーの鍵（秘密の鍵と公開鍵）、本アプリの公開鍵、動いているサーバーの識別子（プロセス、版、待ち受けのアドレス）を、その PC のそのユーザーだけが読める形で保存します。
サーバーは、その PC に本アプリが届くアドレス（Orca の接続先が示す IP アドレス）の、ポート 47823 だけで待ち受けます。ほかのアドレスでは待ち受けません。launchd には登録せず、リーダーの起動のときと、本アプリがつなげなかったときに起動します。
その PC のファイアウォールが新しいプログラムの接続を止めているときは、最初の起動のときに、その PC の画面に出る確認で、利用者が「許可」を押します。本アプリは、ファイアウォールの設定を変えません。
本アプリとサーバーは、お互いの公開鍵を固定します。本アプリは自分の鍵の対を作り、秘密の鍵を OS の資格情報の保管場所に保存し、公開鍵をその PC に渡します。サーバーの公開鍵は、その PC の Orca のターミナルの画面から読んで固定します。つなぐたびに、一時の鍵を交換して、固定した鍵と合わせて、その接続だけの鍵を作り（X25519、HKDF-SHA256）、以降のやりとりは XSalsa20-Poly1305 で暗号化します。固定した鍵の持ち主でなければ、サーバーは何も答えません。秘密の鍵は、ログにも画面にも出しません。
サーバーが答えるのは、版、フォーメーションの記録（`children.json`）を読むこと、閉じたチームメイトを記録から消すこと、止めることだけです。ほかのファイルは読み書きしません。
本アプリが記録を読むのは、流れのペインと一覧を出すときです。読んだ記録は、画面に出すだけで、チームメイトを閉じるときと削除するときに作る一時の写し（終わると消します）のほかは、この Mac に保存しません。
同意を取り消すと、本アプリは、その PC のサーバーを止め、`remote/` を消し、その環境の固定した鍵を消します。その PC のフォーメーションが残っているときは、取り消せません。

### Orca のファイルとエディタ

開発の画面のファイル欄とエディタは、利用者が選んだ worktree のフォルダの一覧とファイルの中身を、Orca を通じて読み、エディタで書き換えたファイルの中身を、Orca を通じて同じ worktree に書き込みます。
読むのは、利用者がフォルダを開いたとき、ファイルをダブルクリックしたとき、ファイル欄を出したままウィンドウにフォーカスが戻ったとき（ルートと開いているフォルダの一覧を読み直します）、次に挙げる書き込みのあとだけです。書き込むのは、そのファイルを開いて入力したときと、利用者がファイル欄のメニューかドラッグでファイルやフォルダを作る、動かす、名前を変える、消すとき、作業ペインの＋の「スクラッチパッド」で `.orca/scratchpad/` に空のファイルを作るときだけです。「削除」は、確認のあとで、そのファイルかフォルダ（中身ごと）をゴミ箱に入れずに消します。
ファイルの中身は、本アプリを終了するまでメモリにだけ置き、本アプリのファイルには保存せず、ログにも出しません。
ファイル欄で「履歴」を選んだとき（履歴を出したままウィンドウにフォーカスが戻ったときも）は、その worktree の git のコミットの一覧（件名、作者の名前、日時、ID）と、利用者が押したコミットで変わったファイルの一覧を、Orca を通じて読みます。ファイルをダブルクリックしたときは、そのコミットとその親のコミットのファイルの中身を、Orca を通じて読みます。履歴では worktree に何も書き込みません。読んだ内容は、本アプリを終了するまでメモリにだけ置き、保存せず、ログにも出しません。
通信の先は Orca だけです（この Mac の Orca、または保存した接続先のサーバーの Orca）。ここで送ったファイルの中身は、Anthropic には送りません。
エディタの自動保存までの時間（数値だけ）は、設定フォルダの `editor-settings.json` に保存します。

## Claude Code による要約

利用者が Todo 画面の追加欄に Slack のメッセージの URL を貼って「要約する」を押したとき、または Slack のスレッドの詳細で「Todo にする」を押したときだけ、本アプリはそのメッセージのスレッドを Slack から読み、利用者のパソコンにある Claude Code（`claude`）を起動して要約します。
Claude Code に渡すのは、そのメッセージと同じスレッドのメッセージの、送信者の ID と本文のテキストと、最も合うプロジェクトを選ばせるための Todoist のプロジェクトの ID と名前の一覧、要約のしかたの指示（既定の文章、または利用者が編集した文章）で、Claude Code を通じて Anthropic のサーバーへ送られます。
1 回に渡すテキストは 10,000 文字までです。
スレッドがそれに収まらないときは、スレッドの最初のメッセージ（2,000 文字まで）、押したメッセージ（4,000 文字まで）、最新の返信（合わせて 3,000 文字まで）を本文のまま渡し（上限を超えたメッセージは、そこで切って、切ったことを書き添えます）、途中のメッセージを、10,000 文字までの塊ごとに別々に Claude Code へ渡して要点にまとめさせ、その要点を最後の要約に加えます（塊は 5 つまでで、スレッドの終わりに近いものから渡します。時間がかかりすぎたり、1 つが失敗したりしたときは、残りの塊は渡しません）。
Claude Code の呼び出しは、このとき最大で 6 回になります。
要約に含まれなかったメッセージの数は、確認用のカードに出ます。
利用者がメールの詳細画面で「AI 要約」を押したときだけ、本アプリは同じように Claude Code を起動して、そのスレッドを要約します。
Claude Code に渡すのは、そのスレッドの件名と、各メッセージの差出人、日時、本文のテキスト（新しいメッセージから順に、合わせて 10,000 文字まで）で、Claude Code を通じて Anthropic のサーバーへ送られます。
メールを開いただけでは渡しません。
メールの要約は、件名の下のカードに表示するだけで、保存せず、Todoist など他へも送りません。本アプリを終了すると消えます。
送ったデータは、Anthropic のポリシーと、利用者の Claude のアカウントの設定に従って扱われます。
利用者が設定の Claude タブの「Todo の要約プロンプト」から要約プロンプトの画面を開き、Claude に指示を送ったときだけ、本アプリは同じように Claude Code を起動して、要約のしかたの指示の編集を手伝わせます。
Claude Code に渡すのは、その画面の編集欄にある指示の文章、それまでの会話、今回の指示で、Slack のメッセージは渡しません。Claude Code を通じて Anthropic のサーバーへ送られます。
編集欄の文章と会話は、本アプリを終了するまで画面にだけ残り、保存しません。利用者が「保存」を押したときだけ、指示の文章を設定フォルダの `todo-prompt.json` に保存します（既定の文章に戻すとこのファイルは消えます）。
利用者が Todo の案のページの「Claude」の欄で依頼を送ったときだけ、本アプリは同じように Claude Code を起動して、案の名前と説明の修正を手伝わせます。
Claude Code に渡すのは、案の名前と説明（そのときの左の欄の内容）、それまでの会話、今回の依頼で、Slack のメッセージとそのリンクは渡しません。Claude Code を通じて Anthropic のサーバーへ送られます。
Claude の提案は、利用者が「適用」を押したときだけ左の欄に入り、適用しても Todoist にはタスクを作りません。会話は、案のページを閉じるまで画面にだけ残り、保存しません。
利用者が Todo 画面の Claude のペインで依頼を送ったときだけ、本アプリは同じように Claude Code を起動して、タスクの案を考えさせます。
Claude Code に渡すのは、それまでの会話（Claude が前に出した案の名前、日付、プロジェクトの名前を含みます）、今回の依頼、今日の日付、Todoist のプロジェクトの ID と名前の一覧で、既存のタスクの本文や Slack のメッセージは渡しません。Claude Code を通じて Anthropic のサーバーへ送られます。
Claude の案はカードで見せ、利用者がカードの「追加」を押したときだけ、カードの名前、日付、プロジェクトで Todoist にタスクを作ります（「却下」では何も作りません）。会話とカードの内容は、本アプリを終了するまで画面にだけ残り、保存しません。
利用者が「Slack に貼る」の画面で依頼の送信を押したときだけ、本アプリは同じように Claude Code を起動して、貼る文章の校正、貼り先の選択、行うことのカードの作成を手伝わせます。
Claude Code に渡すのは、その画面の文章、それまでの会話、今回の依頼、行うことのカードの並び（貼り付け先、カードに書いた文面、投稿済みかどうか）と、貼り先の候補のチャンネルの名前（カードの今の貼り付け先、依頼に貼った Slack のリンクの先、最近使った先と、つないでいるワークスペースの参加しているチャンネル。Slack のメッセージは含みません）で、Claude Code を通じて Anthropic のサーバーへ送られます。
画面を開いただけ、文章を入力しただけでは渡しません。Claude が直した文章はすぐ画面の文章に入りますが、それだけでは Slack へは投稿しません。Slack へ投稿するのは、上の「Slack との連携」に書いた場合だけです。
編集欄の文章と会話は、本アプリを終了するまで画面にだけ残り、保存しません。
どの要約、編集、校正、相談でも、モデルにはファイルを読み書きする道具も MCP サーバーも渡しません。
設定の「スキル」タブで作ったスキルは、「Slack に貼る」の画面と、Slack のスレッドの詳細の Claude 欄で、依頼に添える指示です。
スキルを選んで依頼を送ったときは、そのスキルの名前、説明、指示の文章も、依頼と一緒に Claude Code に渡し、Claude Code を通じて Anthropic のサーバーへ送られます。
依頼のときにスキルを選ぶ画面はまだないので、いまの版では、スキルの文章はどこにも送りません。
Slack のメッセージの要約の結果は、タスクの名前と説明として Todoist に送ります。
設定の Claude タブとサイドメニューに状態（ログイン中のメールアドレスとプラン、Claude Code の版）を出すため、`claude auth status` と `claude --version` を実行します。メッセージの内容は渡しません。

## Anthropic の API キー

利用者が設定の Claude タブで Anthropic の API キーを登録した場合に限り、本アプリは Claude Code を API キーで動かします。
キーは OS の資格情報の保管場所に保存し、画面には表示しません。設定フォルダのファイルには、方式（サブスクリプションか API キーか）だけを `claude-auth.json` に保存します。
キーを登録するとき、そして設定の Claude タブとサイドメニューの状態を確かめるときに、本アプリは Anthropic のサーバー（api.anthropic.com）へキーを付けて、使えるモデルを 1 件尋ねる問い合わせを送ります。メールなど利用者のデータは含みません。
この問い合わせで確かめるのは、キーが使えるかどうかと、キーが属するワークスペースの ID だけです。
要約、編集、校正、相談を行うときは、キーを Claude Code の環境変数として渡し、本アプリが API を直接呼ぶことはありません。コマンドラインの引数やログにはキーを出しません。
API キーに切り替えると、本アプリは `claude auth logout` を実行して、この端末の Claude Code のサブスクリプションをログアウトします。
設定の接続解除で、保存したキーを削除できます。Anthropic の Console のキーは残るので、不要なら Console で取り消してください。

## アップデートの確認

本アプリは、起動したときと 5 分ごとに、GitHub Releases（github.com）の `latest.json` を取得して、新しい版があるかを確かめます。
このとき GitHub には、利用者の IP アドレスなど通常の通信の情報が伝わります。メールなど利用者のデータは送りません。
自動で入れ替えられるのは macOS（Apple Silicon）版だけです。
新しい版があるときの動きは、設定の「アップデート」タブで選べます。
「手動」では、右下のポップアップ（または設定の「アップデート」タブ）の「更新して再起動」を押したときに限り、GitHub Releases から新しい版をダウンロードし、署名を確かめて入れ替えます。
「自動」（初期値）では、新しい版が見つかり次第、裏でダウンロードし、署名を確かめて入れ替えます。
どちらでも、アプリの再起動は、利用者が右下のポップアップ（または設定の「アップデート」タブ）の更新のボタンを押したときだけ行います。

## アクセスの取り消し

本アプリからアカウントを削除すると、本アプリは Google にそのアカウントのアクセス権の取り消しを依頼し、資格情報の保管場所のリフレッシュトークンと設定フォルダのメールアドレスも消します。
取り消しの依頼に失敗しても、本アプリ側の削除は続けます。
Gmail のメールそのものは消えません。

本アプリへのアクセス権は、Google アカウントの「[サードパーティ製のアプリとサービス](https://myaccount.google.com/connections)」からいつでも取り消せます。
保存したリフレッシュトークンは、macOS ではキーチェーンアクセスで「jp.mysis.tsunagiai」の項目を、Windows では資格情報マネージャーの「Windows 資格情報」で名前が「jp.mysis.tsunagiai」で終わる項目を削除すると消せます。
Todoist のトークンは、設定画面の「Todoist の接続を解除」か、同じ場所で「jp.mysis.tsunagiai.todoist」の項目（Windows では名前がそれで終わる項目）を削除すると消せます。
Slack のトークンは、設定画面の「接続を解除」か、同じ場所で「jp.mysis.tsunagiai.slack」の項目（ワークスペースごと。Windows では名前がそれで終わる項目）を削除すると消せます。
データベースの画面のパスワードは、その接続を削除するか、同じ場所で「jp.mysis.tsunagiai.database」の項目（接続ごと。Windows では名前がそれで終わる項目）を削除すると消せます。
Slack の App-Level Token は、設定画面の「リアルタイム更新」の削除ボタンか、ワークスペースの「接続を解除」か、同じ場所で「jp.mysis.tsunagiai.slack-app」の項目（ワークスペースごと。Windows では名前がそれで終わる項目）を削除すると消せます。
キーチェーンアクセスや資格情報マネージャーで消した場合は、設定フォルダの `todoist-cache.json`（最後に取得したタスクの控え）が残るので、手で消してください。
識別子が「jp.mysis.cookapps」だった版の本アプリを使っていた場合は、新しい版が最初の起動で、その設定フォルダ（macOS では `~/Library/Application Support/jp.mysis.cookapps`、Windows では `%APPDATA%\jp.mysis.cookapps`）の中身を新しい名前へ写し、同じ場所の「jp.mysis.cookapps」で始まる項目は、その項目を最初に使うときに値を新しい名前へ写します。
古い設定フォルダと古い項目は残るので、不要なら手で消してください（設定画面の接続解除やアカウントの削除は、古い項目も消します）。

v0.14.6 以前（旧名 cookup）の本アプリを使っていた場合は、同じ場所の「jp.mysis.cookup」で始まる項目と、旧設定フォルダ（macOS では `~/Library/Application Support/jp.mysis.cookup`、Windows では `%APPDATA%\jp.mysis.cookup`）も手で消してください。旧名の項目のアクセス権は、上の「サードパーティ製のアプリとサービス」から取り消せます。
