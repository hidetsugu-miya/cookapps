# プライバシーポリシー

最終更新日: 2026年11月2日

cookapps（以下「本アプリ」）は、利用者自身のパソコン（macOS または Windows）上で動くデスクトップ Gmail クライアントです。
本アプリが Google アカウントのデータをどう扱うかを説明します。

## 取得するデータ

本アプリは、利用者の同意を得て、Gmail API と Google Calendar API から次のデータを取得します。

- 受信トレイのスレッドの一覧（差出人、件名、日時、抜粋、既読状態）
- 利用者が開いたスレッドのメッセージ本文
- ログインした各アカウントのメールアドレス
- 受信トレイを最新に保つための、メールボックスの変更履歴（history）。約 10 秒ごとに確認します
- 利用者のカレンダーの一覧（表示の対象になっているカレンダーのIDと色）
- 表示中の週の予定（タイトル、開始・終了の日時、利用者自身の出欠の状態、場所、説明、Meet のリンク、参加者の人数と承諾した人数、カレンダーの名前）。参加者の名前とメールアドレスは取得しません。カレンダーを開いたとき、週を移したとき、表示中は 5 分ごとに取得します
- Claude との連携（`cookapps-mcp`）を利用者が設定した場合は、MCP クライアントからの呼び出しに応じて、上と同じ種類のデータを取得します。予定は、呼び出しで指定された期間のものを取得します
- Claude との連携（`cookapps-mcp`）を利用者が設定した場合は、MCP クライアントからの呼び出しに応じて、上と同じ種類のデータを取得します。予定は、呼び出しで指定された期間のものを取得します

要求するスコープは次の 2 つです。

- `https://www.googleapis.com/auth/gmail.modify`
- `https://www.googleapis.com/auth/calendar.readonly`（予定を閲覧するためだけに使い、予定の作成・編集・削除はしません）

利用者が Todoist に接続した場合は、Todoist のサーバーから、タスク（名前、説明、期限、優先度、サブタスク、ラベル）とプロジェクトとラベルも取得します。
アプリを起動したとき、Todo 画面を開いたとき、ウィンドウに戻ったとき、約 10 秒ごと（前回からの変更だけ）、タスクを操作したあとに取得します。
サイドメニューの Todo に、期限の時刻を過ぎたタスクの件数を表示するためです。
タスクの詳細を開いたときは、そのタスクのコメント（投稿者、日時、本文、添付ファイルの名前と URL）も取得します。
投稿者の名前を調べるため、Todoist の自分のユーザー情報と、自分以外の人が書いたコメントがあるときはそのプロジェクトの共同編集者の一覧も取得します。

## データの使い方

取得したデータは、本アプリの画面に表示するためだけに使います。
例外は、利用者が「Todo にする」を押したスレッドの件名と、アカウントのメールアドレスを含む Gmail の URL を Todoist に送ることと、利用者がコメントの送信を押したときにそのコメントの文章と選んだファイルを Todoist に送ることです。
約 10 秒ごとに変更履歴を確認し、変わったスレッドの一覧用の情報（差出人、件名、日時、抜粋、既読状態）だけを取り直して画面に反映します。
利用者の操作に応じて、スレッドのゴミ箱への移動と、受信トレイからの除外（アーカイブ）を Gmail API に依頼します。
利用者が「元に戻す」を押したときは、その取り消し（ゴミ箱からの復元、受信トレイへの戻し）も依頼します。
また、スレッドの既読・未読の切り替えも Gmail API に依頼します。
未読のスレッドを開いたときも、既読にするよう依頼します。
カレンダーの予定は、画面に表示するためだけに使います。
`cookapps-mcp` を設定した場合は、取得したデータを、利用者が設定した MCP クライアント（Claude Code など）へ渡します。
スレッドのゴミ箱への移動、アーカイブ、既読・未読の切り替えも、そのクライアントからの呼び出しに応じて Gmail API に依頼します。
メールの送信、削除（ゴミ箱を経由しない削除）、設定の変更はしません。

## 保存

ログインの維持に使うリフレッシュトークンは、アカウントごとに OS の資格情報の保管場所（macOS ではキーチェーン、Windows では資格情報マネージャー）へ保存します。
ログインしたアカウントのメールアドレスの一覧は、本アプリの設定フォルダに保存します。
「画像を表示」を押した送信者のメールアドレスの一覧も、設定フォルダに保存します。
起動直後や画面を開いた直後に、取得を待たずに前回の内容を表示するため、受信トレイのスレッドの一覧（差出人、件名、日時、抜粋、既読状態）と、表示した週のカレンダーの予定（最大 10 週。場所や説明などの詳細を含みます）を設定フォルダのファイルに保存します。
受信トレイは、すべてのアカウントを全件読み込めたとき、カレンダーは、すべてのアカウントとカレンダーを取得できた週だけ、新しい内容に書き換えます。
アカウントを削除すると、この 2 つのファイルも消えます。
カレンダーの週の始まりの曜日の設定も、設定フォルダに保存します。
Orca の画面のエディタの自動保存までの時間の設定も、設定フォルダの `editor-settings.json` に保存します（時間の数値だけです）。
画面ごとの書体と大きさの設定も、設定フォルダの `font-settings.json` に保存します（書体の名前と大きさの数値だけです）。
Todoist に接続している場合は、同じ目的と、取得に失敗したときの表示のために、Todoist のタスクとプロジェクトとラベルを設定フォルダのファイルに保存します。
Todoist の接続を解除すると、このファイルも消えます。
メールの本文は保存せず、本アプリを終了すると消えます（`cookapps-mcp` も同じで、上のファイルも書きません）。

## 第三者への提供

本アプリには開発者が運営するサーバーがなく、取得したデータを開発者へ送信しません。
第三者へ渡すのは、利用者が `cookapps-mcp` を MCP クライアントに設定し、そのクライアントが呼び出した場合と、利用者が Todoist に接続して「Todo にする」を押した場合（スレッドの件名と、アカウントのメールアドレスを含む Gmail の URL）と、利用者が Todoist のタスクのコメントの送信を押した場合（コメントの文章と、選んだファイル。Todoist のサーバーへ）と、利用者が Slack に接続して「貼る」を押した場合（編集欄の文章。初めはスレッドの最新のメッセージの件名、差出人、日時、本文のテキストで、利用者が編集したもの）と、利用者が Slack のスレッドの詳細で「返信する」を押した場合（返信の文章。Slack へ）と、利用者が Slack に貼る文章の校正で Claude に依頼を送った場合（編集欄の文章、それまでの会話、今回の依頼。Claude Code を通じて Anthropic へ）と、利用者が Slack のスレッドの詳細の Claude 欄で Claude に依頼を送った場合（返信欄の文章、開いているスレッドのメッセージ（送信者の名前、日時、画面に出ている本文。ボットの投稿のブロックと添付の文字、ボタンと添付のリンクの URL を含む）、それまでの会話、今回の依頼。Claude Code を通じて Anthropic へ）と、利用者が Slack のメッセージの URL を貼って「要約する」を押した場合、または Slack のスレッドの詳細で「Todo にする」を押した場合（そのメッセージと、同じスレッドのメッセージの送信者の ID と本文のテキスト。長いスレッドは、途中を何回かに分けて。それと、Todoist のプロジェクトの ID と名前の一覧。Claude Code を通じて Anthropic へ）と、利用者が Todo の要約プロンプトの編集画面で Claude に指示を送った場合（編集欄の指示の文章、それまでの会話、今回の指示。Slack のメッセージは含みません。Claude Code を通じて Anthropic へ）と、利用者が Todo の案のモーダルの「Claude と直す」で Claude に依頼を送った場合（案の名前と説明、それまでの会話、今回の依頼。Slack のメッセージは含みません。Claude Code を通じて Anthropic へ）と、利用者がメールの詳細画面で「AI 要約」を押した場合（そのスレッドの件名と、各メッセージの差出人、日時、本文のテキスト。Claude Code を通じて Anthropic へ）と、利用者が「Orca に渡す」欄で「要約する」または「直す」を押した場合（指示の文章、カードに出ている内容、それまでの会話、直しの依頼。メールのスレッド、Slack のスレッド、Todo のタスクのテキスト。Claude Code を通じて Anthropic へ）と、利用者が「Orca に渡す」欄で「この内容で Orca に渡す」または「送る」を押した場合（合意した要約または追加の指示の文章と、カードに出ている内容。メールのスレッド、Slack のスレッド、Todo のタスクのテキスト。Orca へ。保存した接続先を選んでいるときは、その接続先の Orca へ。Orca が動かす Claude を通じて Anthropic へ）と、利用者が Anthropic の API キーを登録した場合（キーの確認の問い合わせ。キーだけを Anthropic へ）だけです。
渡したデータは、そのクライアントと提供元（Claude であれば Anthropic）のポリシーに従って扱われます。
本アプリが通信するのは Google のサーバーと、利用者が接続した場合の Todoist のサーバー、利用者が Slack のトークンを設定した場合の Slack のサーバー（App-Level Token を登録した場合は、つなぎ続ける Slack の WebSocket を含みます）、利用者が「要約する」「Todo にする」「AI 要約」を押した場合、「Orca に渡す」欄で「要約する」または「直す」を押した場合、Todo の要約プロンプトの編集画面で Claude に指示を送った場合、Todo の案のモーダルの「Claude と直す」で Claude に依頼を送った場合、Slack に貼る文章の校正または Slack のスレッドの詳細の Claude 欄で Claude に依頼を送った場合の Claude Code を通じた Anthropic のサーバー、利用者が API キーを登録した場合のキーの確認のための Anthropic のサーバー、利用者が「Orca に渡す」欄で「この内容で Orca に渡す」または「送る」を押した場合の Orca（この Mac の Orca、または保存した接続先のサーバーの Orca。そこで動く Claude を通じた Anthropic のサーバー）、利用者が Slack の画面を開いた場合の送信者と自分のアイコンを配る画像サーバー（`slack-edge.com` とそのサブドメイン、`secure.gravatar.com` だけ。トークンは送りません）、利用者が「画像を表示」を押した送信者のメッセージの画像の送り主のサーバー、利用者が Slack のスレッドの詳細で「画像を表示」を押したメッセージの画像の置き場のサーバー（Slack 以外の任意のサーバー。https のみで、トークンは送りません）、新しい版を確かめる GitHub のサーバー（GitHub Releases）だけです。
HTML 形式のメールに含まれる画像は、既定では読み込みません。
利用者がメッセージの「画像を表示」を押したときだけ、そのメッセージの画像を送り主のサーバーから取得します（https のみ）。
このとき、そのメッセージの送信者のメールアドレスを覚え、以後はその送信者のメッセージを開いたときに、画像を自動で取得します。
覚えた送信者を外す画面はありません。外すには、アプリを終了してから、設定フォルダの `image_senders.json` からそのメールアドレスを消してください。
自動で取得するのは、Gmail が付けた認証結果（Authentication-Results）が DMARC 合格、または From のドメインと一致する DKIM 署名の合格のメッセージだけです。
そうでないメッセージは、覚えた送信者のものでも、「画像を表示」を押すまで取得しません。
このとき、取得先のサーバーに利用者の IP アドレスが伝わり、メールが開かれたことが送り主に知られることがあります。
スタイルシートなど、画像以外の外部のものは読み込みません。
メール本文のリンク（http と https のみ）は、利用者が押したときだけ、既定のブラウザで開きます。
本アプリ自身はそのリンクの先と通信しません。

## Todoist との連携

利用者が Todoist の個人 API トークンを入力した場合に限り、本アプリは Todoist のサーバーと通信して、タスクとプロジェクトを表示・操作します。
「Todo にする」を押したスレッドの件名と、アカウントのメールアドレスを含む Gmail の URL を Todoist に送り、トークンは OS の資格情報の保管場所に保存して、設定画面の「Todoist の接続を解除」で消せます。
取得したタスクとプロジェクトとラベルは、起動直後や Todo 画面を開いた直後と、Todoist に接続できないときに前回の内容を表示するため、設定フォルダに保存し、接続を解除すると消します。
コメントは保存せず、本アプリを終了すると消えます。
コメントの文章と、利用者が選んだファイルは、利用者がコメントの送信を押したときだけ Todoist に送ります。入力しただけ、ファイルを選んだだけでは送りません。

## Slack との連携

利用者が Slack の User OAuth Token を設定に入力した場合に限り、本アプリは Slack のサーバー（slack.com）と通信します。
トークンはワークスペースごとにいくつでも入力でき、入力したときに Slack の `auth.test` で確かめ、設定画面を開いたときにも確かめます。
「Slack に貼る」を開くと、選んだワークスペースの参加しているチャンネルの名前を Slack から取得し、本アプリを閉じるまでメモリにだけ覚えます。
Slack のリンクを入力したときは、そのチャンネルの名前を Slack から取得します。
トークンは OS の資格情報の保管場所にワークスペースごとに保存し、設定画面の「接続を解除」で、そのワークスペースのトークンを Slack に取り消して消せます。画面には表示しません。
メールの内容を Slack に送るのは、利用者がメールの詳細画面で「Slack に貼る」の「貼る」を押したときだけです。
送るのは、「Slack に貼る」の画面の編集欄の文章（10,000 文字まで）です。
編集欄には、初めにスレッドの最新のメッセージの件名、差出人、日時、本文のテキスト（3,000 文字まで）が入り、利用者が自由に直せます。送る内容は、利用者が編集した文章です。
編集欄の文章、宛先、Claude との会話は、本アプリを終了するまでメモリにだけ残り、保存しません。
ワークスペースの ID、名前、ユーザー名、URL は、設定フォルダの `slack-workspaces.json` に保存します。
貼れた宛先（ワークスペースの ID、チャンネル ID、チャンネル名、スレッドの識別子）は、新しい順に 8 件まで、同じ場所の `slack-recent.json` に保存します。メールの内容は保存しません。
送ったメッセージは、利用者の Slack ワークスペースと Slack のポリシーに従って扱われます。

### Slack のリアルタイム更新（App-Level Token）

利用者が設定の「Slack」タブの「リアルタイム更新」で App-Level Token（`xapp-` で始まる）をワークスペースごとに登録した場合に限り、本アプリは Slack の Socket Mode の WebSocket（`slack.com` のサブドメインの `wss` のアドレス。`apps.connections.open` で Slack が毎回知らせるもの）を開き、本アプリを起動している間はつなぎ続けます。切れたときは、間隔をのばしながら自動でつなぎ直し、つなぎ直したときは一覧を読み直します。
この接続で Slack から届くのは、トークンを取ったアプリの Event Subscriptions で利用者が選んだ、パブリックとプライベートのチャンネルのメッセージのイベント（投稿、スレッドの返信、編集、削除）です。本アプリはイベントを受け取ったことを Slack に返すだけで、イベントの中身は保存せず、どのチャンネル（とスレッド）が変わったかを知るためだけに使います。DM とグループ DM のイベントと、そのほかのイベントは、返信して捨てます。
イベントがあったチャンネルは、そのつど、上の「Slack の一覧とスレッド」と同じ呼び出し（`conversations.history`、スレッドの返信は `conversations.replies`、まだ知らない名前は `users.info`）で Slack から読み直し、メモリにだけ置きます。同じチャンネルのイベントは 1 秒ごとにまとめ、同じチャンネルを読み直すのは 10 秒に 1 回まで、1 つのワークスペースでは 1 分に 20 回の呼び出しまでにします（超えた分は、あとでまとめて読みます）。一覧に出さないチャンネルのイベントは捨て、読みません。
App-Level Token は、OS の資格情報の保管場所にワークスペースごとに保存し、画面にもログにも出しません。Slack に拒否されたら、消します。

### Slack の一覧とスレッド

本アプリは、起動したときと、ウィンドウが見えている間の 1〜2 分ごとに（Slack の画面を開いていないときも。サイドメニューの Slack のアイコンに未読の数を出すためです。App-Level Token を登録して、すべてのワークスペースがつながっている間は 5 分ごとです）、トークンのユーザーが参加しているパブリックとプライベートのチャンネル（DM とグループ DM は除く）のメッセージ、スレッドの返信、ユーザーの名前とアイコンを、Slack から読みます。
読んだメッセージの本文、ブロックと添付のカードの文字、名前、アイコンの URL、添付ファイルの名前は、本アプリを終了するまでメモリにだけ置き、保存しません。
ユーザーの名前は 1 時間、メモリに覚えます。
送信者と自分のアイコンは、Slack の画像サーバー（`slack-edge.com` とそのサブドメイン）と Gravatar（`secure.gravatar.com`）から、トークンを付けずに取得します。Slack が別のホストのアイコンの URL を返したときは取得せず、名前の頭文字を出します。取得した画像は、本アプリを終了するまでメモリにだけ置きます。
スレッドの詳細を開いたときは、添付された画像のサムネイルを `files.slack.com` から、トークンを付けて取得し、本アプリを終了するか、そのワークスペースを削除するまで、メールの画像とは別のメモリにだけ置きます（保存しません）。トークンは、`files.slack.com` 以外へは送りません。
アイコンとサムネイルの取得のために、利用者の IP アドレスが、その画像サーバーに知られます。
ボットやアプリの投稿は、ブロックや添付のカードに画像を入れることがあります。
その画像は、既定では読み込みません。
利用者がスレッドの詳細のメッセージの「画像を表示」を押したときだけ、そのメッセージの画像を、画像の URL のサーバーから取得します（https のみ）。
そのサーバーは Slack 以外の任意のサーバーで、利用者の IP アドレスが伝わります。
Slack のトークンは付けません。トークンが要る Slack の画像（`files.slack.com`）は取得しません。
取得した画像は、メールの画像と同じメモリに、本アプリを終了するまでだけ置き、保存しません。
返信の文章を Slack に送るのは、利用者がスレッドの詳細で「返信する」を押したときだけです（10,000 文字まで）。入力しただけでは送りません。返信の文章は、本アプリを終了するまでメモリにだけ残り、保存しません。
返信の文章とスレッドのメッセージを Anthropic に送るのは、利用者がスレッドの詳細の Claude 欄で依頼を書いて送信を押したときだけです。送るのは、返信欄の文章（空のこともあります）、開いているスレッドのメッセージ、それまでの会話、今回の依頼です。
スレッドのメッセージは、送信者の名前、日時、画面に出ている本文で、ボットの投稿のブロックと添付の文字、ボタンと添付のリンクの URL も含みます（Claude が返信案でリンクを扱えるようにするためです）。長いスレッドは、新しいメッセージを優先して合わせて 10,000 文字までにし、古いものを省きます。読めたのがスレッドの途中までのときは、その旨も添えます。
Claude Code を通じて Anthropic のサーバーへ送られます。会話は、本アプリを終了するまでメモリにだけ残ります。
一覧とスレッドの読み出しには、トークンのスコープ `channels:history`・`groups:history`・`channels:read`・`groups:read` が要ります。名前とアイコンには `users:read`、添付画像には `files:read`、ユーザーグループへのメンションの名前には `usergroups:read` を使い、なければその分だけ出ません（メンションは「@不明」と出ます）。
ユーザーグループへのメンションを名前で出すために、ワークスペースごとにユーザーグループの ID とハンドルを `usergroups.list` で読みます（無効にしたグループも含みます）。ID とハンドルは、本アプリを終了するか、そのワークスペースを削除するまで、メモリにだけ置き、保存しません。1 時間ごとに読み直し、失敗したときは 5 分後に読み直します。
また、一覧の未読と既読を分けるために、メッセージを保持しているチャンネル（1 回の読みにつき 1 ワークスペースで最大 40 件）の既読位置（Slack の `last_read`）を、`conversations.info` で読みます。既読位置は、本アプリを終了するか、そのワークスペースを削除するまで、メモリにだけ置き、保存しません。
一覧のメッセージを開くと、そのチャンネルの既読位置をそのメッセージまで進めるよう、`conversations.mark` で Slack に送ります（すでに既読のメッセージを開いても送りません）。これには `channels:write`（公開チャンネル）と `groups:write`（非公開チャンネル）が要り、なければ送らず、未読の表示も変えません。この 2 つのスコープは、Slack の仕様で、チャンネルの管理権限も含みますが、本アプリは既読位置を送る `conversations.mark` にしか使いません。足さなくても、既読を Slack と同期すること以外は使えます。
一覧の上のヘッダーの「すべて既読にする」を 2 回押したときは、一覧に出ていない分も含め、本アプリが持っている未読のメッセージのあるチャンネルごとに、既読位置をそのチャンネルの最新の未読のメッセージまで進めるよう、`conversations.mark` で Slack に送ります（同じワークスペースには、同時に 4 件まで。呼び出し制限に当たったら、そのワークスペースのその回は打ち切ります）。一覧に出さないチャンネルと、上の 2 つのスコープのないワークスペースには送りません。
利用者が一覧の行のボタンで「一覧に出さない」を選んだチャンネルは、ワークスペースの ID とチャンネルの ID だけを、設定フォルダの `slack-hidden.json` に保存します（メッセージの本文や名前は保存しません）。そのチャンネルは、メッセージも既読位置も Slack から読みません。ただし、そのチャンネルでウォッチしているスレッドは、外すまで読みます。設定の Slack タブで戻すか、そのワークスペースを削除すると、消えます。Slack 側のミュートは読まず、変えません。
利用者が一覧の行のしおりで「ウォッチ」を選んだスレッドは、ワークスペースの ID、チャンネルの ID、スレッドの `ts`、最後に開いたときの最新の返信の `ts` だけを、設定フォルダの `slack-watched.json` に保存します（メッセージの本文、名前、アイコンは保存せず、本アプリを終了するまでメモリにだけ置きます）。ウォッチしたときと、一覧を読み込むたびに（確かめたのが古いものから 20 件まで）、そのスレッドの先頭のページを `conversations.replies` で Slack から読み、最初のメッセージと新しい返信の数を出します。呼び出し制限に当たったら、そのワークスペースのその回は打ち切り、Slack が示す時間が過ぎるまで確かめません。外すか、そのワークスペースを削除すると、消えます。
一覧には、未読の返信のあるスレッドも出します。そのために、一覧を読み込むたびに、本アプリが持っている返信のあるメッセージのスレッドの先頭のページを `conversations.replies` で Slack から読みます（確かめる順に、全ワークスペースで 1 回 20 件まで。呼び出し制限の扱いはウォッチと同じです）。本文、名前、アイコンは、本アプリを終了するまでメモリにだけ置きます。
Slack にはスレッドの既読位置を書き込む公開の API がないので、本アプリでスレッドを読んでも、Slack 側のスレッドの未読は消えません。本アプリで読んだ位置は、ワークスペースの ID、チャンネルの ID、スレッドの `ts`、読んだ最新の返信の `ts` だけを、設定フォルダの `slack-thread-seen.json` に保存します（新しいものから 500 件まで。メッセージの本文や名前は保存しません）。そのワークスペースを削除すると、消えます。

## Orca との連携

メール、Slack のスレッド、Todo の詳細の右側にある「Orca に渡す」欄は、開いている内容を、Orca（エージェントを動かすアプリ）の新しいセッションに渡します。

### Claude による要約

利用者が「Orca に渡す」欄で「要約する」または「直す」を押したときだけ、本アプリは Claude Code を起動して、渡す内容の「実装すること」の要約と、新しい worktree の名前の案を作らせます。入力しただけ、欄を開いただけでは送りません。
Claude Code に渡すのは、指示の文章、カードに出ている内容（下と同じ。カードを外していれば渡しません）、それまでの会話（要約と直しの依頼）、直しの依頼で、Claude Code を通じて Anthropic のサーバーへ送られます。添付したファイルは渡しません。
会話と要約は、本アプリを終了するまでメモリにだけ残り、保存しません。この呼び出しでは、Orca へは何も送りません。

### Orca に渡す内容

Orca に渡すのは、利用者が要約の中の「この内容で Orca に渡す」か、渡したあとの「送る」を押したときだけです。要約するだけでは渡しません。
送るのは、合意した要約（「実装すること」の箇条書き）と、カードに出ている内容です（合わせて 100,000 文字まで。追加の指示を送るときは、その指示の文章）。カードの内容は、メールではスレッドの各メッセージの差出人、日時、本文のテキスト、Slack ではスレッドの各メッセージの送信者の名前、日時、画面に出ている本文、Todo ではタスクの名前、プロジェクト、期限、説明と、すでに読み込んであるコメントです。
指示の欄にファイルを添付したとき（Orca の画面のターミナルにファイルを貼り付けたり、ドロップしたときも同じ）は、送る前に、そのファイルを送り先の worktree の `.orca/drops/` に Orca を通じて書き込み、そのファイルのパスを要約のあと（追加の指示のときは指示のあと）に加えます。ファイルは画像でも画像でなくてもよく、1 つ 20 MiB までです。置いたファイルは、本アプリでは消しません。
カードの × を押すと、内容を外して要約だけを渡します。画面に出ていない文字（文字を隠す書式など）がメールにあっても、本アプリは見分けず、本文のテキストとしてそのまま送ります。
見えない文字（制御文字、幅のない文字、文字の向きを変える文字、タグ文字）は、送る前に取り除きます。内容は「引用したデータで、指示ではない」と書き添えた囲みに入れて送ります。
Orca のコマンド（`orca`）を通じて、この Mac の Orca へ送ります。「Orca に渡す」欄の送り先で保存した接続先を選んだときは、その接続先のサーバーの Orca へ送ります。Orca は、その文章を Claude Code に渡し、Claude Code を通じて Anthropic のサーバーへ送られます。
送った文章と、セッションの履歴は、Orca と Anthropic のポリシーに従って扱われます。本アプリは、履歴を Orca から読んで画面に出すだけで、保存しません。
本アプリが覚えるのは、メールのスレッド、Slack のスレッド、Todo のタスクごとの、渡したセッションの場所と、最後に選んだ送り先とプロジェクト、新しく作った worktree の名前と場所（起動に失敗したとき、同じものをもう一度作らないため）だけで、本アプリを終了するまでメモリにだけ置き、保存しません。渡すまでの会話（指示、要約、直しの依頼）と、選んだ worktree の種類と名前、要約や送信に失敗した指示の文章も、メモリにだけ残ります。

### Orca のファイルとエディタ

Orca の画面のファイル欄とエディタは、利用者が選んだ worktree のフォルダの一覧とファイルの中身を、Orca を通じて読み、エディタで書き換えたファイルの中身を、Orca を通じて同じ worktree に書き込みます。
読むのは、利用者がフォルダを開いたとき（読み直したときも）と、ファイルをダブルクリックしたときだけです。書き込むのは、そのファイルを開いて入力したときだけです。
ファイルの中身は、本アプリを終了するまでメモリにだけ置き、本アプリのファイルには保存せず、ログにも出しません。
通信の先は Orca だけです（この Mac の Orca、または保存した接続先のサーバーの Orca）。ここで送ったファイルの中身は、Anthropic には送りません。
エディタの自動保存までの時間（数値だけ）は、設定フォルダの `editor-settings.json` に保存します。

## Claude Code による要約

利用者が Todo 画面の追加欄に Slack のメッセージの URL を貼って「要約する」を押したとき、または Slack のスレッドの詳細で「Todo にする」を押したときだけ、本アプリはそのメッセージのスレッドを Slack から読み、利用者のパソコンにある Claude Code（`claude`）を起動して要約します。
Claude Code に渡すのは、そのメッセージと同じスレッドのメッセージの、送信者の ID と本文のテキストと、最も合うプロジェクトを選ばせるための Todoist のプロジェクトの ID と名前の一覧、要約のしかたの指示（既定の文章、または利用者が編集した文章）で、Claude Code を通じて Anthropic のサーバーへ送られます。
1 回に渡すテキストは 10,000 文字までです。
スレッドがそれに収まらないときは、スレッドの最初のメッセージ（2,000 文字まで）、押したメッセージ（4,000 文字まで）、最新の返信（合わせて 3,000 文字まで）を本文のまま渡し（上限を超えたメッセージは、そこで切って、切ったことを書き添えます）、途中のメッセージを、10,000 文字までの塊ごとに別々に Claude Code へ渡して要点にまとめさせ、その要点を最後の要約に加えます（塊は 5 つまでで、スレッドの終わりに近いものから渡します。時間がかかりすぎたり、1 つが失敗したりしたときは、残りの塊は渡しません）。
Claude Code の呼び出しは、このとき最大で 6 回になります。
要約に含まれなかったメッセージの数は、確認用のカードに出ます。
利用者がメールの詳細画面で「AI 要約」を押したときだけ、本アプリは同じように Claude Code を起動して、そのスレッドを要約します。
Claude Code に渡すのは、そのスレッドの件名と、各メッセージの差出人、日時、本文のテキスト（新しいメッセージから順に、合わせて 10,000 文字まで）で、Claude Code を通じて Anthropic のサーバーへ送られます。
メールを開いただけでは渡しません。
メールの要約は、件名の下のカードに表示するだけで、保存せず、Todoist など他へも送りません。本アプリを終了すると消えます。
送ったデータは、Anthropic のポリシーと、利用者の Claude のアカウントの設定に従って扱われます。
利用者が Todo 一覧の見出しの Claude のアイコンか、設定の Claude タブの「Todo の要約プロンプト」から要約プロンプトの画面を開き、Claude に指示を送ったときだけ、本アプリは同じように Claude Code を起動して、要約のしかたの指示の編集を手伝わせます。
Claude Code に渡すのは、その画面の編集欄にある指示の文章、それまでの会話、今回の指示で、Slack のメッセージは渡しません。Claude Code を通じて Anthropic のサーバーへ送られます。
編集欄の文章と会話は、本アプリを終了するまで画面にだけ残り、保存しません。利用者が「保存」を押したときだけ、指示の文章を設定フォルダの `todo-prompt.json` に保存します（既定の文章に戻すとこのファイルは消えます）。
利用者が Todo の案のモーダルの「Claude と直す」で依頼を送ったときだけ、本アプリは同じように Claude Code を起動して、案の名前と説明の修正を手伝わせます。
Claude Code に渡すのは、案の名前と説明（そのときの左の欄の内容）、それまでの会話、今回の依頼で、Slack のメッセージとそのリンクは渡しません。Claude Code を通じて Anthropic のサーバーへ送られます。
Claude の提案は、利用者が「適用」を押したときだけ左の欄に入り、適用しても Todoist にはタスクを作りません。会話は、モーダルを閉じるまで画面にだけ残り、保存しません。
利用者が「Slack に貼る」の画面で「校正する」か送信を押したときだけ、本アプリは同じように Claude Code を起動して、貼る文章の校正を手伝わせます。
Claude Code に渡すのは、その画面の編集欄にある文章、それまでの会話、今回の依頼で、Claude Code を通じて Anthropic のサーバーへ送られます。
編集欄を開いただけ、文章を入力しただけでは渡しません。Claude の提案は、利用者が「適用」を押したときだけ編集欄に入り、適用しても Slack へは投稿しません。
編集欄の文章と会話は、本アプリを終了するまで画面にだけ残り、保存しません。
どの要約、編集、校正、相談でも、モデルにはファイルを読み書きする道具も MCP サーバーも渡しません。
Slack のメッセージの要約の結果は、タスクの名前と説明として Todoist に送ります。
設定の Claude タブとサイドメニューに状態（ログイン中のメールアドレスとプラン、Claude Code の版）を出すため、`claude auth status` と `claude --version` を実行します。メッセージの内容は渡しません。

## Anthropic の API キー

利用者が設定の Claude タブで Anthropic の API キーを登録した場合に限り、本アプリは Claude Code を API キーで動かします。
キーは OS の資格情報の保管場所に保存し、画面には表示しません。設定フォルダのファイルには、方式（サブスクリプションか API キーか）だけを `claude-auth.json` に保存します。
キーを登録するとき、そして設定の Claude タブとサイドメニューの状態を確かめるときに、本アプリは Anthropic のサーバー（api.anthropic.com）へキーを付けて、使えるモデルを 1 件尋ねる問い合わせを送ります。メールなど利用者のデータは含みません。
この問い合わせで確かめるのは、キーが使えるかどうかと、キーが属するワークスペースの ID だけです。
要約、編集、校正、相談を行うときは、キーを Claude Code の環境変数として渡し、本アプリが API を直接呼ぶことはありません。コマンドラインの引数やログにはキーを出しません。
API キーに切り替えると、本アプリは `claude auth logout` を実行して、この端末の Claude Code のサブスクリプションをログアウトします。
設定の接続解除で、保存したキーを削除できます。Anthropic の Console のキーは残るので、不要なら Console で取り消してください。

## アップデートの確認

本アプリは、起動したときと 5 分ごとに、GitHub Releases（github.com）の `latest.json` を取得して、新しい版があるかを確かめます。
このとき GitHub には、利用者の IP アドレスなど通常の通信の情報が伝わります。メールなど利用者のデータは送りません。
自動で入れ替えられるのは macOS（Apple Silicon）版だけです。
新しい版があるときの動きは、設定の「アップデート」タブで選べます。
「手動」では、右下のポップアップ（または設定の「アップデート」タブ）の「更新して再起動」を押したときに限り、GitHub Releases から新しい版をダウンロードし、署名を確かめて入れ替えます。
「自動」（初期値）では、新しい版が見つかり次第、裏でダウンロードし、署名を確かめて入れ替えます。
どちらでも、アプリの再起動は、利用者が右下のポップアップ（または設定の「アップデート」タブ）の更新のボタンを押したときだけ行います。

## アクセスの取り消し

本アプリからアカウントを削除すると、本アプリは Google にそのアカウントのアクセス権の取り消しを依頼し、資格情報の保管場所のリフレッシュトークンと設定フォルダのメールアドレスも消します。
取り消しの依頼に失敗しても、本アプリ側の削除は続けます。
Gmail のメールそのものは消えません。

本アプリへのアクセス権は、Google アカウントの「[サードパーティ製のアプリとサービス](https://myaccount.google.com/connections)」からいつでも取り消せます。
保存したリフレッシュトークンは、macOS ではキーチェーンアクセスで「jp.mysis.cookapps」の項目を、Windows では資格情報マネージャーの「Windows 資格情報」で名前が「jp.mysis.cookapps」で終わる項目を削除すると消せます。
Todoist のトークンは、設定画面の「Todoist の接続を解除」か、同じ場所で「jp.mysis.cookapps.todoist」の項目（Windows では名前がそれで終わる項目）を削除すると消せます。
Slack のトークンは、設定画面の「接続を解除」か、同じ場所で「jp.mysis.cookapps.slack」の項目（ワークスペースごと。Windows では名前がそれで終わる項目）を削除すると消せます。
Slack の App-Level Token は、設定画面の「リアルタイム更新」の削除ボタンか、ワークスペースの「接続を解除」か、同じ場所で「jp.mysis.cookapps.slack-app」の項目（ワークスペースごと。Windows では名前がそれで終わる項目）を削除すると消せます。
キーチェーンアクセスや資格情報マネージャーで消した場合は、設定フォルダの `todoist-cache.json`（最後に取得したタスクの控え）が残るので、手で消してください。
v0.14.6 以前（旧名 cookup）の本アプリを使っていた場合は、同じ場所の「jp.mysis.cookup」で始まる項目と、旧設定フォルダ（macOS では `~/Library/Application Support/jp.mysis.cookup`、Windows では `%APPDATA%\jp.mysis.cookup`）も手で消してください。旧名の項目のアクセス権は、上の「サードパーティ製のアプリとサービス」から取り消せます。
