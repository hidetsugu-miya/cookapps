# Orca

Orca は、エージェントを動かすデスクトップアプリです。

サイドメニューの「開発」のアイコン（コードの形）で、開発の画面を開く。
開発の画面は、左の一覧に、見出し「フォーメーション」の下のフォーメーションと、見出し「プロジェクト」の下の Orca のプロジェクトを並べる。
プロジェクトかセッションを押すと、右に Orca の作業ペインを出す。フォーメーションの行を押すと、その代わりに、[オーケストレーション](#オーケストレーション)のリーダーとチームメイトを出す。
フッターにモードの切り替えは無い（フッターにはベルだけが残る）。
起動したときは作業ペインで、「Orca の画面で開く」も、プロジェクトとセッションを選ぶので、いつも作業ペインで開く。

## 一覧

見出し「プロジェクト」の下に、Orca のプロジェクトを一覧する（状態のアイコンとセッション数を出す。SSH の接続先は並べない）。
フォーメーションのチームメイトのセッションは、プロジェクトの下にも、作業ペインのタブにも出さず、セッション数にも数えない（チームメイトは[フォーメーションの行の下](#フォーメーションの一覧)に出る）。チームメイトが作業していても、そのプロジェクトは開かず、作業中のプロジェクトにも入れない。
隠すのは、つなぎAI がチームメイトのために作った worktree のセッションと、既にあったフォルダで動くチームメイト自身のセッションだけ。既にあったフォルダの、あなたのセッションは、そのままプロジェクトの下に出る。
作業中のセッションがあるプロジェクトは上に集め、入った順に固定する（作業が進んでも入れ替わらず、新しく作業が始まったものが先頭に入る）。その下に、セッションはあるが作業中ではないプロジェクトを並べ、セッションの無いプロジェクトはその下に並べる（どちらも最近動いた順）。
プロジェクトの行の矢印で、そのプロジェクトのセッションの行を開閉する（行は 1 段字下げして並ぶ。複数のプロジェクトを同時に開ける）。セッションの行には、自分の質問と Claude の回答のうち新しい方の 1 行を出す（どちらにも文が無いときは、Orca と同じく会話の名前。タブの名前は会話の名前のまま）。出すのは自分の質問と Claude の回答だけで、Claude Code が会話に差し込んだ要素（`<event>` など）、`[stderr]` の行、貼ったデータや JSON の返答は出さない。サブエージェントが作業中のセッションは、行の右端にロボットのアイコンと作業中の数を出す。
最初は作業中のプロジェクトがすべて開いていて、閉じたプロジェクトも、新しいセッションが作業を始めると開き直す。
行を押すとそのタブを選び、右のペインでタブを押すと、その行が選ばれる。
一覧の上の検索欄に打った文字で、プロジェクトを名前で絞り込む（Orca 画面のどこにいても Cmd+J で検索欄に移れ、↓↑で行を動き、Enter で選び、Escape で消す）。
入力待ちと、完了や中断で止まって未確認のセッションの件数はサイドメニューのアイコンに出す。作業中のセッションがある間は、アイコンが黄色になってゆっくり明滅する。フォーメーションのチームメイトのセッションも、この件数と明滅、通知に数える。SSH の接続先のセッションは、この件数にも Dock のバッジにも数えない。一覧の幅はドラッグで変えられる。

### 接続先

接続先は、このマシンか Orca に保存したサーバーの 1 つ（`orca` CLI と Orca のペアリング情報を使う。アプリは履歴を保存しない）。
接続先は設定フォルダの `orca-settings.json` に保存したもので、アプリの中に切り替える場所は無い（ファイルがまだ無いときは、Orca に保存した最初のサーバー。サーバーが無ければこのマシン）。
読み込めなかったときは、一覧の上のお知らせに理由を出す。
保存したサーバーが接続先のときは、このマシンのプロジェクトとセッションも同じ一覧に混ぜて出し、保存したサーバーのプロジェクトの行には、サーバーの名前のチップを付ける（セッションの行には付けない）。
このときは、このマシンと保存したサーバーを別々に読む。
読み込めなかった場所ごとに、お知らせに「{場所} を読み込めませんでした: {理由}」を 1 行ずつ出す。
場所の名前は、このマシンなら「このマシン」、保存したサーバーならその名前。
片方だけ読めなかったときは、もう片方の行はそのまま出す。次に読めると、その場所の行は消える。

### プロジェクトを追加する

一覧の見出しの右端の「プロジェクトを追加」のボタンを押すと、小さなポップアップが開く。
「場所」のセレクトで、この Mac か、接続先の保存した環境を選ぶ（開くたびにこの Mac から始まる）。
「フォルダを選ぶ…」を押して、追加するフォルダを選ぶ。

この Mac は、システムのフォルダ選択のダイアログで選ぶ。取り消すと何も追加しない。

保存した環境は、そのサーバーのフォルダを見て選ぶ画面を開く。
上の「上のフォルダ」、「ホーム」、パンくずで、フォルダを移る。
絞り込む欄に打った文字で、名前を絞り込む。「/」で始まるパスを打って Enter を押すと、そのパスへ移る。
↓↑で行に印を付けて Enter を押すと、そのフォルダに入る。
下には、追加するパスを出す（印を付けた行か、今のフォルダ）。「フォルダを選ぶ」で追加し、「キャンセル」か Escape で閉じる。

Git のリポジトリでないフォルダは、フォルダとして追加する。
追加できたら、一覧をすぐに読み直す。
失敗したときは理由を出し、一覧は読み直さない。

## セッション

右のペインではプロジェクトのセッションをタブで切り替え、タブから閉じられる。
どのタブもターミナルで、Claude のセッションにもそのまま打ち込める。
右のペインのタブ列の右端の＋から、「Claude を起動」か「ターミナルを開く」を選ぶと、左ペインで選んでいるプロジェクトの worktree で始める。
worktree が 2 つ以上あるときは、選ぶ画面を出す。
つなぎAI がフォーメーションのチームメイトのために作った worktree は、選ぶ画面に出さず、数にも入れない（既にあったフォルダで動くチームメイトのフォルダは出す）。
始めたセッションとターミナルは一覧に現れるとタブで開く。
＋の 3 つ目の「スクラッチパッド」は、メモのファイルを作って開く（[スクラッチパッド](#スクラッチパッド)）。

### モーダルでのぞく

一覧のセッションの行を右クリックすると、画面の中央にモーダルが開き、そのセッションのターミナルが出る。
選んでいるプロジェクトを変えずに、様子を見て、そのまま打ち込める。
プロジェクトの行を右クリックすると、そのプロジェクトの最初のセッションが出る。
上の段には、状態のアイコン、プロジェクトの名前、セッションの題名が並ぶ。保存したサーバーのセッションには、サーバーの名前も出る。タブは出ない。
「開く」を押すと、モーダルを閉じて、そのプロジェクトとセッションを選んだ状態に移る。
Escape か ✕ で閉じると、作業ペインは元のまま。
選んでいるプロジェクトの行、セッションの無いプロジェクト、ターミナルの無いセッションでは開かない（ターミナルは一度に 1 か所にしか出せないため）。
セッションが一覧から消えたときと、そのプロジェクトを選んだときは、モーダルは閉じる。

## ターミナル

保存したサーバーが接続先のときは、Orca が送るターミナルの出力を描く（色も出る）。
ターミナルはいつもペインの大きさに合わせて描く。
このマシンが接続先のときは、Orca が出力を送れないので、画面を毎秒読んで写す。
色は出ず、`claude` のような全画面のプログラムは近似になる。

### コピー

`claude` のようにマウスを使うプログラムでは、ドラッグで選んだ文字列をプログラムが送り、それがクリップボードに入る。
入らなかったときは、⌘C か「編集 > コピー」で入る。
Option を押しながらドラッグすると、プログラムではなくターミナル側で文字を選べる。

### ファイル

ターミナルには、ファイルを貼り付けるか、ドロップできる。画像でも、画像でないファイルでもよい（Finder でコピーしたファイルも貼り付けられる）。
ファイルは、そのセッションの worktree の `.orca/drops/` に、元の名前で置かれる。同じ名前があるときは、`名前 copy.拡張子` のように名前を変える。
置いたファイルのパスがターミナルに入力される（Claude がそのパスからファイルを読む）。画像のパスは貼り付けとして入力し、画像でないファイルのパスは打ち込む。
このマシンの worktree と、保存したサーバーの worktree で使える。ファイルを書く権限のないペアリングでは使えない。
20 MiB まで置け、置いたファイルは自動では消えない。読めないファイル（フォルダなど）を含むときは、どれも置かない。

### ターミナルの配色

設定の「Orca」タブの「ターミナルの配色」で、ターミナルの配色を選ぶ。
「外観」で「システムに合わせる」「ライト」「ダーク」から選ぶ。
「ライト」か「ダーク」にすると、システムの外観に関係なく、そのテーマで描く。
ライトとダークのテーマは別々に選ぶ。
「システムに合わせる」のときは、システムの外観に合わせて切り替わる（Orca の外観の設定には合わせない）。
選べるのは Orca の組み込みのテーマで、色の見本が出る。
初めての選択は、この Mac の Orca の設定から取る（読めたときの 1 回だけ。Orca の設定は読むだけで、書き換えない）。
Orca に足したテーマや、組み込みにないテーマのときは、ライトは Builtin Tango Light、ダークは Ghostty Default Style Dark になる。
Ghostty の設定を取り込んでいても、色はここで選んだテーマを使う。
フォントは、設定の「フォント」タブでターミナルの書体を選んだときはそれを使い、「Ghostty の設定に従う」のままなら Ghostty の設定を使う（キーは Ghostty の設定のまま）。

## ファイルとエディタ

「ファイル欄」のボタンで、選んでいるタブの worktree のファイルを木で出す。
タブが無いときは、左の一覧で選んでいるプロジェクトの主の worktree（リポジトリ本体のフォルダ）を出す。
ファイルやフォルダの行を右クリックすると、「パスのコピー」と「相対パスをコピー」のメニューが出る。
メニューには、作る、動かす、消す項目もある（[ファイルの操作](#ファイルの操作)）。
ファイルの行のメニューには「ダウンロード」もある。押すと保存ダイアログが出て、選んだ場所にそのファイルをこの Mac へ保存する（保存した環境のファイルも同じ）。
ボタンは、ファイル欄を隠しているときは右上のペインのタブ列の右端に、出しているときはファイル欄の上の段の右端にある。
フォルダは押すと開き、中身を Orca から読む。もう一度押すと閉じる。
一度読んだフォルダは、開き直しても読み直さない。
ディスクでファイルが増えたり減ったりした分は、10 秒ごとと、ウィンドウにフォーカスが戻ったときに出る。そのとき、ルートと開いているフォルダを読み直す（ファイル欄を隠している間と、ウィンドウが隠れている間は読まない）。読み直すボタンは無い。
変わっていなければ描き直さないので、選択とスクロールはそのまま残る。
git が無視するファイルとフォルダは、薄い斜体で出す（一覧を先に出し、斜体は少し遅れて付く）。
HEAD と違うファイルとフォルダは、色で出す（[git の差分](#git-の差分)）。
ファイルをダブルクリックする（か、選んで Enter を押す）と、タブで開いて、その場で書き換えられる。
同じファイルをもう一度開くと、そのタブを選ぶ。
入力が止まって、設定の「Orca」タブの「エディタ」の「自動保存までの時間」（100 から 3000 ms、初めは 1000 ms）が過ぎると、自動で保存する。保存のボタンはない。
エディタの書体と大きさは、設定の「フォント」タブで選ぶ。
本文の左には行番号が出る。行番号は選択にもコピーにも入らない。
カーソルのある行には、幅いっぱいに薄い帯が敷かれる。範囲を選んでいる間と、エディタからフォーカスが外れたときは消える。文字の色は変わらない。
未保存の入力があるタブには、印が付く。
タブを閉じるときと、ウィンドウを閉じるときも、入力があれば保存する。
開く前に読んだ内容とディスクのファイルが違っていたら（別のところで書き換えられたか、消えたとき）、上書きしない。
そのときは見出しに理由が出て、入力は画面に残り、そのタブはもう保存しない。
ペインに出しているファイルは、ファイル欄を出している間、10 秒ごとにディスクの内容を読み直す。別のタブに隠れていたファイルは、出したときに読み直す。
ディスクの内容が変わっていたら、未保存の入力が無いときだけ、その内容に置き換える。カーソルとスクロールの位置は変わらない。
未保存の入力があるタブは読み直さない。
ペインに出している HEAD との差分のタブも、同じ間隔で読み直す。

Markdown のファイルは、見出し、リスト、表、コード、チェックリストを文書の形で描くリッチな表示で開く。
エディタの見出しの右端の 2 つのボタンで、ソース（`<>`）とリッチな表示（鉛筆）を切り替える。選んだ方は、タブを閉じるまで残る。
リッチな表示のまま書き換えられ、ソースと同じく自動で保存する。片方で打った内容は、切り替えるともう片方に出る。
リッチな表示では、行が折り返すので、カーソルのある段落（見出し、リストの項目、表のセルなど）に、ソースと同じ帯が敷かれる。
保存するときは、変えた行だけをファイルに入れる。触っていない行の書き方（箇条書きの記号、空白など）と、先頭のフロントマターはそのまま残る。
書き方をそのまま残せないファイルは、ソースで開き、リッチな表示は読むだけになる。書き換えが元の行に当てられなかったときは、ソースに切り替えてエラーを出す。
リッチな表示では、外部の画像は読み込まない。

開けるのは、384 KiB までの UTF-8 のテキストで、改行が LF だけか、全部の行が CRLF のファイルだけ。
バイナリのファイル、UTF-8 でないファイル、改行が混ざっているファイルは、開けない。
このマシンの worktree と、保存したサーバーの worktree で使える。

ファイル欄の見出しのブランチ名を押すと、真下にブランチの一覧が開く。
一覧は「ローカル」と「リモート」に分かれ、今のブランチに印が付く。
別の worktree で使っているブランチは薄く出て、選べない。
上の欄に打つと一覧を絞り込み、リモートのブランチはその文字で探す。
ブランチを選ぶと、その worktree をそのブランチに切り替える。リモートのブランチを選ぶと、それを追うローカルのブランチを作って切り替える。
切り替えると、ファイル一覧と見出し、ペインに出しているファイルと差分を読み直す。開いているタブは閉じない。
アプリの外（ターミナルなど）でブランチを切り替えたときも、次の一覧の読み直し（10 秒ごと）で見出しが変わり、同じように読み直す。
コミットしていない変更があるときや、マージの途中、セッションが動いているときなど、Orca が断ったときは、その文言が出る。
新しいブランチはここでは作れない。

### git の差分

ファイルの木では、HEAD と違うファイルとフォルダの、名前とアイコンに色が付く。
変更したもの（変更、削除、名前の変更など）は琥珀色、新しいもの（追跡していないものと、追加したもの）は緑。太字にはしない。
行の右端には、ファイルなら `M`（変更）か `U`（新規）、中に差分のあるフォルダなら点が、同じ色で出る。
選んでいる行は、白のまま。git が無視するものは、薄い斜体のまま色が付く。
色は、フォルダを出したあとに少し遅れて付く。ファイルの木を読み直すとき（10 秒ごと、フォーカスが戻ったとき、作る・動かす・消すのあと、ブランチを切り替えたあと）に付け直す。
確かめられなかったときは何も出さず、前の色を残す。

### ファイルの操作

フォルダの行を右クリックすると、メニューの先頭に「新規ファイル」と「新規フォルダー」が出る。
選ぶと、そのフォルダが開き、中の先頭に名前の欄が出る。Enter で作り、Escape か空の名前でやめる。
木の何もないところを右クリックしても同じ 2 つが出て、worktree の直下に作る。
新しいファイルは、エディタのタブで開く。同じ名前があるときは「同じ名前があります」と出て、何も作らない。

ファイルやフォルダの行を右クリックして「移動・名前の変更」を選ぶと、行がその場で worktree からのパスの欄になり、名前の部分が選ばれる。
書き換えて Enter を押すと、そのパスへ動かす。途中の無いフォルダは作る。Escape でやめる。
行をドラッグして、フォルダの行に落としても動かせる。木の何もないところに落とすと、worktree の直下へ動く。閉じたフォルダは、上で少し止まると開く。
移動先に同じ名前があるときは上書きせず、「同じ名前があります」と出る。
動かしたファイルを開いているタブは、入力を残したまま、新しいパスになる。

行を押すと、その行が選ばれて、アクセント色の地に白い文字で出る。
⌘ を押しながら押すと、選びに足すか、選びから外す。Shift を押しながら押すと、前に押した行から今の行までを選ぶ。
フォルダの行は、押すと選んで開閉する。⌘ か Shift を押しながらのときは、選ぶだけで開閉しない。
ファイルの行をダブルクリックすると開く。

メニューの最後の赤い「削除」か、Delete キーで、選んだ行を消す。
2 つ以上選んでいるときのメニューは、赤い「n 件を削除」だけになる。
「{名前} を完全に削除します。元に戻せません。」（2 つ以上のときは「n 件を完全に削除します。元に戻せません。」）の確認を出し、「削除」を押すと消す。確認は 1 回だけ。
選んだフォルダとその中の行がどちらも選ばれているときは、フォルダだけを消す。
ゴミ箱には入らず、元に戻せない。フォルダは中身ごと消える。
途中で消せない行があるときは、そこで止めて理由を出す。それまでに消えた行は、消えたものとして出す。
消したファイルを開いているタブは、保存せずに閉じる。

作る、動かす、消すのあとは、そのフォルダを読み直す。

### スクラッチパッド

右のペインの＋の「スクラッチパッド」は、worktree の `.orca/scratchpad/` にメモのファイルを作り、エディタのタブで開く。
選ぶと、＋の下に名前の欄が出る。`.orca/scratchpad/` は固定で、名前は初め `memo.md`。拡張子は自由に変えられる。
Enter か「作って開く」で作り、Escape か「やめる」でやめる。
同じ名前のファイルがあるときは、作らずにそのファイルを開く。
worktree が 2 つ以上あるときは、先に選ぶ画面を出す。

### 履歴

ファイル欄の上の段の左の 3 つのアイコン、「ファイル」「履歴」「言語サーバー」で、ファイルの木、git の履歴、言語サーバーの状態と設定（[言語サーバー](#言語サーバー)）を切り替える。
起動したときはファイルが出ている。選んだ方は、どの worktree でも同じで、アプリを終了するまで残る。
履歴を出しているときにウィンドウにフォーカスが戻ると、履歴を初めから読み直す。読み直すボタンは無い。
履歴を出している間は、10 秒ごとに新しいコミットを確かめる。増えていれば一覧の先頭に出て、変わっていなければ一覧はそのまま残る。
履歴は、ファイル欄が出している worktree のコミットを、HEAD から新しい順に 50 件ずつ並べる。行には件名、短い ID、日時が出て、マウスを乗せると作者の名前が出る。
一覧の末尾までスクロールすると、続きを読む。別の worktree に移ると、その worktree の一覧を読み直す。ブランチを切り替えたときも読み直す。
コミットを押すと、一覧の下に、そのコミットで変わったファイルが出る。行には、変わり方（M 変更、A 追加、D 削除、R 名前の変更、C コピー）、名前、フォルダ、増えた行と消えた行の数が出る（バイナリのファイルには数が出ない）。5,000 件を超える分は「ほか N 件」と出る。
ファイルをダブルクリックする（か、選んで Enter を押す）と、そのファイルの差分を作業ペインのタブで出す。左が親のコミットのファイル、右がそのコミットのファイルで、見た目とボタンは、ファイルの右クリックの「差分を表示」で出す HEAD との差分と同じ。
タブの名前と見出しには、コミットの短い ID が付く。同じコミットの同じファイルをもう一度開くと、そのタブを選んで読み直す。
履歴は読むだけで、worktree には何も書かない。

### 定義

エディタ（ソースの表示）で開いたファイルの名前を、⌘ を押しながら右クリックすると、言語サーバーでその定義を探す。
ファイルの言語を受け持つサーバーがあるときだけ働く。初めは、ruby-lsp が Ruby を受け持つ。
受け持つサーバーが無い言語と、⌘ なしの右クリックは、今までどおり。
サーバーが索引中や停止中のときは、定義は探せず、その理由がタブに出る。探すだけでは、サーバーは起動しない（[言語サーバー](#言語サーバー)）。

⌘ を押している間、マウスを名前の上に 0.15 秒置くと、定義がある名前に下線が引かれ、カーソルが指の形になる。
下線は印だけで、押しても開かない。開くのは右クリック。
定義が無い名前、エラー、サーバーが索引中か停止中のときは、何も出ない。

定義は、エディタのタブの真下にペインを割って、「定義 ・ {名前}」のタブで出す。
タブはプロジェクトに 1 つで、次に探すと、どのペインにあっても、同じタブの中身が置き換わる。
タブは閉じるボタンで閉じる。タブが無くなったペインも閉じる。タブは保存しないので、アプリを起動し直すと出ない。
ファイル欄の表示は変わらない。

タブの上には、名前と「{n} 件」が出る。探している間は、回るマークが出る。
断られたときと、サーバーが答えなかったときは、その理由が出る。候補が無いときは、「定義はありません」と「0 件」が出る。
候補の行には、worktree の中のファイルなら worktree からのパスと行、外のファイルならファイル名と行が出る。その下に、worktree の中のフォルダが出る。
worktree の外（gem）の定義には、gem の名前と版とフォルダ（「railties 8.1.4.1 / lib」）が出て、Ruby のファイルには「gem」の印が付く。
どの行も初めから開いていて、定義の行の前後 3 行が、行番号付きで出る（ファイルの端では少ない）。定義の行には印が付く。
読めなかった行には、その理由が出る。ほかの行はそのまま。
行の「開く」で、その場所をエディタのタブで開き、定義の行を真ん中にして移る。
開くのは、定義を探したファイルのタブがあるペイン。そのタブが無いときは、定義のタブ以外の最初のペイン。
開いてあるファイルは、そのタブを選んで移る。
gem のように worktree の外のファイルは、鍵のアイコンの読み取り専用のタブで開く。保存も、読み直しもしない。確認なしで閉じる。

### 言語サーバー

ファイル欄の上の段の「言語サーバー」のボタンで、言語サーバーの欄に切り替える。
欄は、出している間だけ読む。
言語サーバーは、リポジトリごとにいくつでも持てる。サーバーごとに、受け持つ言語を決める。1 つの言語を受け持つサーバーは 1 つ。
何も保存していないリポジトリには、ruby-lsp が 1 つあり、Ruby を受け持ち、自動で起動する。

欄の上の段は、見出し「言語サーバー」と、サーバーを足す＋。
保存した環境の worktree では、その下に「ssh の接続先」の選択欄が出る。この Mac の `~/.ssh/config` の Host から選ぶ。空にもでき、保存した Host が一覧に無いときも、選択肢に残る。
その下に、サーバーごとのカードが並ぶ。

カードの上の段には、点、サーバーの名前、状態（索引中、動作中、停止中）、再起動、メニュー（削除）、開閉のボタンが出る。
点は、索引中が黄、動作中が緑、停止中が灰、失敗で止まったときが赤。
開けるカードは 1 枚で、ほかのカードを開くと閉じる。初めは、失敗したサーバーのカードが開き、なければ先頭のカードが開く。
閉じたカードには、「状態 ・ 言語 ・ 起動の方法」の 1 行が出る。
状態は、読み込むときに 1 度読み、あとはサーバーの状態の変わりに合わせて変わる。

開いたカードには、次の欄が出る。
- 名前
- 言語。言語のチップは、×で外す。＋で、検索付きのメニューから足す（そのサーバーがもう受け持つ言語は出ない）。
- 起動の方法。「compose の {サービス}」「ホスト」「方法なし」のどれか。サービスの候補が 2 つ以上のときは、使うサービスの選択欄が付く。
- 起動コマンド
- worktree（この Mac のパス、読み取り専用）と、サーバーから見た worktree のパス（パスの対応）
- 自動で起動
- 「自動に戻す」。起動コマンド、パスの対応、サービスを自動の決め方に戻す。どれも設定していないときは押せない。
- 「コンテナを起動」。サービスのコンテナが止まっているときだけ出る。

起動コマンドとパスの対応には、決まった値が入る。設定していなければ「自動」の印が付き、手で書いた値には付かない。
カードの頭の下に、直前に失敗した操作（保存、再起動、コンテナの起動）の理由、止まった理由、起動の方法を読めなかった理由が、先に見つかったもの 1 つ出る。
名前と言語の断りも、同じ行に出る。

欄は、離れると保存する（リポジトリごとに、設定フォルダの `lsp-settings.json`）。
変えていない欄は、保存しない。空にした欄は、設定していないことになり、自動の決め方に戻る。
保存は、変えたサーバーだけに触る。名前を変えると、古い名前で動いていたサーバーは止める。
入力している欄は、読み直しや別の欄の保存で書き換えない。
設定を変えても、動いているサーバーはそのまま。再起動のボタンで、新しい設定のサーバーに起動し直す。再起動しても、gem の定義の行とタブはそのまま読める。

＋は、「server-1」のような名前のカードを開く。言語を 1 つ足すまでは保存せず、足したときに、入力した欄といっしょに保存する。
カードを開いているまま別のプロジェクトを出すと、保存していないカードは消える。
メニューの「削除」は、確認のあと、そのサーバーを設定から外し、動いているものを止める。保存していないカードは、消すだけ。
サーバーが 1 つも無いリポジトリにもできる。
欄を出している間は、2 秒ごとに設定を読み直す。Claude Code が `tsunagiai-mcp` で変えた設定が、ここに出る（[Claude との連携（MCP）](mcp.md)）。
入力中の文字と、開いているカード、保存していないカードはそのまま残る。

起動の方法は、worktree から決める。
compose のファイルがあれば、worktree をマウントしているサービスの中で、`docker compose exec` でサーバーを動かす。
compose のファイルが無いか、どのサービスも worktree をマウントしていなければ、Ruby を受け持つサーバーは、`Gemfile.lock` に ruby-lsp があるときに、ホストで `bundle exec ruby-lsp` を動かす。
Ruby を受け持たないサーバーには、起動コマンドが決まっていない。「起動コマンド」に、標準入出力で LSP を話すコマンドを書く。
起動コマンドは、worktree の中で `/bin/sh -c` が動かす（compose のときは、サービスの中）。書いたとおりに動く。
保存した環境の worktree では、この Mac の `ssh` で接続先のマシンで動かす。

「自動で起動」が入っていれば、そのサーバーが受け持つ言語のファイルを開いたときに、サーバーを起動する。
その worktree のタブ（セッション、ターミナル、ファイル、差分、定義）がひとつも開いていないとき、worktree が Orca の一覧から消えたとき、アプリを終了したときに、サーバーを止める。
一度止まったサーバーは、次にその言語のファイルを開いたときに、また起動する。失敗や、コンテナが止まっての停止は、自動では起動し直さない。再起動か、「コンテナを起動」を押す。
「コンテナを起動」は、コンテナを起動してから、サーバーを起動する。アプリが自分でコンテナを起動することはない。
定義を探す前に、ディスクで変わった、そのサーバーが受け持つ言語のファイルを、サーバーに知らせる。

## Orca に渡す

開いているメール、Slack のスレッド、Todo の内容を、その画面のペインから Orca に渡す。
メールと Slack のスレッドでは画面の右側にペインが開く。
Todo では、開いているタスクの見出しの「編集」の左にある「Orca に渡す」のボタンを押すと、詳細のコメントの下にペインが開く（タスクを開いているあいだだけ押せる）。
ペインは上から、送り先、プロジェクト、worktree のチップ、渡す内容のカード、指示の欄の順に並ぶ。
始めるのは新しいセッションだけで、動いているセッションには渡せない。
送り先（このマシンか、保存したサーバー）と、その中のプロジェクトを選ぶ。
プロジェクトのメニューの上の検索欄に打った文字で、プロジェクトを名前で絞り込む（↓↑で行を動き、Enter で選び、Escape で閉じる）。
送り先を選んでも、Orca の画面の接続先は変わらない。

### worktree

worktree のチップのメニューには、選んだプロジェクトの worktree が並ぶ。
プロジェクト本体のフォルダ（default）が先頭で、「新規作成」が最後に付く。
つなぎAI がフォーメーションのチームメイトのために作った worktree は並ばない（既にあったフォルダで動くチームメイトのフォルダは並ぶ）。
各行は名前と、その下に今そこで開いているブランチを出す。チップは「名前 ・ ブランチ」と出る。
上の検索欄に打った文字で、名前とブランチを絞り込む。
既存の worktree を選ぶと、そのフォルダでセッションを始める。渡すときに、ブランチは切り替えない。

「新規作成」を選ぶと、チップの下に枠が出て、名前、作成元、ブランチを決める。
名前は、新しい worktree の名前。
作成元は、新しい worktree の元にするブランチで、ローカルとリモートのブランチの一覧から選ぶ。選ばなければ、Orca の既定になる。
ブランチは、「新しいブランチ」か「既存のブランチ」のどちらか。
「新しいブランチ」では、その名前を書く。空なら、名前は Orca が決める。
「既存のブランチ」では、一覧から選ぶ。別の worktree が使っているブランチと、本体のフォルダが今開いているブランチは選べない。作成元は選べなくなる。
既存のブランチを選んだとき、Orca がそのブランチを開くかどうかは、まだ実機で確かめていない。
ブランチや作成元に、git が断る文字（空白、`..`、`~`、`:` など）や、`-` で始まる名前があると、worktree を作る前に断る。
選んだものは項目ごとにメモリにだけ置く（保存しない）。

### 渡す

指示は、書いたまま渡る。Claude は要約しない。
右下の矢印のアイコン（Cmd+Enter でもよい）を押すと、Claude がカードの内容を箇条書きに要約し、新しいセッションが起動する。
要約を作っているあいだと渡しているあいだは押せない。指示が空のときと、プロジェクトを選んでいないときも押せない。
Orca に渡る文は、書いた指示、添付したファイルのパス、内容の要約、元の内容の引用の順。
カードの × で外すと、要約も引用もなく、指示だけが渡る。
カードがあるのに Claude が使えないときは、押せない（カードを外せば渡せる）。
指示の欄にも、ファイルを貼り付けるか、ドロップして添付できる（添付したファイルは欄の上に並び、× で外せる。画像はサムネイル、画像でないファイルは名前で出る）。
ファイルは渡す前に、送り先の worktree の `.orca/drops/` に置かれ、そのパスが指示のあとに加わる（Claude には送らない）。
使えるファイルと接続先は、ターミナルと同じ。

### 渡したあと

渡すと、ペインはそのセッションのターミナルに変わる。
上には、「リポジトリ ・ ブランチ」と状態、「Orca の画面で開く」のボタン、閉じるアイコンが並ぶ。
ターミナルにはそのまま打ち込め、ファイルも貼り付けかドロップで添付できる。Claude の質問には、ここで答える。
このマシンのセッションは、画面を読んで写す（色は出ず、全画面のプログラムは近似になる）。
保存したサーバーのセッションも出す。
閉じるアイコンを押すまでは、別の項目に移って戻っても、同じセッションを出す。閉じると、次は渡す画面に戻る。
Orca からなくなったセッションは「終了」と出て、ターミナルは止まる。

## オーケストレーション

リーダーの Claude Code に仕事を頼むと、リーダーが仕事をチームメイトのセッションに分け、Orca で進める。
仕事のまとまりごとにフォーメーションを作り、フォーメーションごとにリーダーとチームメイトを持つ。
リーダーは effort high、チームメイトは effort medium の Claude Code で動く。
画面は、左の一覧、中のペイン、右の「流れ」の 3 つ。
中のペインの上のタブ（リーダーと、チームメイトごとのタブ）で、出すターミナルを切り替える。
右の「流れ」は幅 260px で固定し、中のペインが残りの幅を取る。
一覧を閉じているときは、中のペインのタブ列の左端のボタンで開き直せる。
サイドメニューの「開発」のアイコンには、Orca と同じ、確認待ちのセッションの数と、作業中の黄色の明滅が出る。チームメイトのセッションも、ここに数える。
フォーメーションのチームメイトの数は、一覧のフォーメーションの行に出す。

### フォーメーションの一覧

一覧の行には、名前と、右端に起動しているチームメイトの数を出す（時間とプロジェクトは出さない）。予定に入れただけのチームメイトは数えず、終わったチームメイトは閉じるまで数える。起動しているチームメイトがいなければ、数は出さない。名前の前の点は、リーダーが入力待ちでなければ、灰色の輪になる。
リーダーが入力待ち（Claude Code があなたの入力を待っている）のときは、点がオレンジに塗られ、行の右端に「入力待ち」の札が付く。起動していないリーダーは、入力待ちにしない。
行を押すと、中のリーダーとチームメイトのタブと、右の流れが、そのフォーメーションのものに切り替わる。前のフォーメーションのリーダーは止まらない。
アプリを起動したときは、どのフォーメーションも選ばず、作業ペインを出す。リーダーとチームメイトは、行を押してから出る。
起動したチームメイトは、フォーメーションの行の下に、1 段字下げして記録の順に並ぶ（保存した環境のフォーメーションも同じ）。
チームメイトのいるフォーメーションの行には、左に矢印が付き、チームメイトの行を畳んだり開いたりできる。最初は開いている。矢印を押しても、フォーメーションは選ばない。
チームメイトの行には、セッションと同じ状態のアイコン、チームメイトの名前、その下に薄い字で「{プロジェクト} ・ {ブランチ}」を出す（ブランチが無いときは、プロジェクトだけ）。
チームメイトの行を押すと、そのフォーメーションを選び、そのチームメイトのタブを出して、キーの入力を移す（「自動で追う」は切れる）。ターミナルを閉じた完了のチームメイトは、フォーメーションを選び、リーダーのタブのままにする。
行を右クリックすると、メニューの上にそのフォーメーションのプロジェクトが並び、その下に「削除」がある。
見出しの「＋」で作成の窓を開き、名前とプロジェクト（この Mac と Orca に保存した接続先ごとのリポジトリ。選ばなくてもよい）を選んで「作成」を押すと、フォーメーションを作って選ぶ。リポジトリの無い環境と、読めなかった環境は、見出しも出さない。
プロジェクトは、上の欄に打った文字で絞り込める。絞り込むたびに、一覧は先頭に戻る。
作成、環境の読み込み、同意で出たエラーは、次の操作（「作成」をもう一度押す、作成の窓を開き直す、「同意する」をもう一度押す）の始めに消える。
フォーメーションは一つの PC のものなので、プロジェクトは一つの環境のものだけ選べる。二つの環境にまたがるプロジェクトは、理由を出して断る。
作るときに、選んだプロジェクトのリポジトリの、Orca の worktree の場所を `.claude/worktrees` にする（[チームメイト](#チームメイト)）。
リーダーは、選んだプロジェクトを最初の指示にして起動する（再起動のときも同じ）。
メニューの「削除」を押すと、確かめてから削除する。まずチームメイトをすべて、閉じるときと同じように確かめ、閉じられないチームメイト（コミットしていない変更、追跡していないファイル、どのリモートにも無いコミットがある）がいれば、何も閉じず、リーダーも止めずに、そのチームメイトごとに理由と、変更のあるファイル、追跡していないファイル、どのリモートにも無いコミット、worktree の場所を出す。
そこで「強制削除」を押すと、出したチームメイトの worktree を消してからフォーメーションを削除する。変更と追跡していないファイルは失われ、どのリモートにも無いコミットはローカルのブランチに残す（残したブランチは一覧の上に出す）。出したあとに増えたチームメイトが閉じられないときは、強制せずに、そのチームメイトをまた出す。
すべて閉じられるときは、リーダーを終え（保存した環境のフォーメーションは、その Orca のリーダーのターミナルも、チームメイトより先に閉じる。閉じられずに残っているときは、チームメイトを閉じずに、理由を出して削除を止める）、チームメイトを閉じ、フォーメーションのフォルダを消す。保存した環境のフォーメーションは、閉じたチームメイトを、その PC のチームメイトの記録（この Mac に残る古い記録のチームメイトは、その記録）からも外す。チームメイトを閉じている間にリーダーがチームメイトを足したときは、フォルダを消さずに、もう一度削除するよう伝える。最初からあるフォーメーション `formation` も、ほかと同じく消せる。
出していたフォーメーションを消すと、どれも選んでいない状態に戻り、作業ペインを出す。

### リーダー

中のペインの「リーダー」のタブは、フォーメーションのある PC で動く Claude Code。
Claude Code の SendMessage は同じ PC のセッションにしか届かないので、リーダーはチームメイトと同じ PC に置く。
この Mac のフォーメーションのリーダーは、アプリが自分で開いたターミナルで動く（Orca は通さない）。
フォーメーションを初めて選んだときに起動する。ほかの行や画面に移っても止まらず、戻ると同じものが出る。Claude Code が自分で終わったときは、次に出したときに起動し直す。
権限のモードは auto、effort は high で、組み込みの道具（Bash など）も使える。
フォーメーションの名前は、右の流れのリーダーのカードに出る。リーダーが入力待ちのときは、リーダーのタブにもオレンジの印が付く。
タブ列の右端の再起動のボタンで、出しているフォーメーションのリーダーを終わらせて新しく始める（`exit` で終わったあとも押せる）。新しい起動が済むまでは押せない（保存した環境のリーダーの、最初の起動の間も押せない）。チームメイトのタブを選んでいる間も押せない（リーダーのターミナルが見えていないため）。ほかのフォーメーションのリーダーと、チームメイトには触らない。
Orca に保存した接続先のフォーメーションのリーダーは、その接続先の Orca に作るターミナルで動く。
ターミナルは、プロジェクトのリポジトリではなく、その Orca のフローティングのターミナル（どのリポジトリにも属さず、ホームのフォルダで開くもの）に作る。
その PC の `tsunagiai-mcp` でリーダーを起動する。
使うのは、つなぎAI がその PC の設定フォルダの `remote/` に置いた `tsunagiai-mcp` で、探しはしない。
先にそれでサーバー（下の「その PC のサーバー」）を起動してから、リーダーになる。
置いていないと、ターミナルに「tsunagiai-mcp が置かれていません」と出て、Claude Code は立ち上がらない。その言葉が読めるように、ターミナルはシェルを開いて残る。
起動の文はターミナルのシェルと置き換わるので、Claude Code が終わると、そのターミナルも閉じる（起動の文やプロンプトは残らない）。
次にそのフォーメーションを出したとき（一覧で押し直すか、リーダーのタブを選び直したとき）に、新しいターミナルで起動し直す。ターミナルがまだ残っていれば、それを出す。
最初の指示は、その PC から見たプロジェクト（環境は `local`）として、Claude Code の起動のときに渡す。
アプリは、Claude Code が入力待ちになるのを待たず、何も送らない。
新しいフォルダで初めて起動するときは、Claude Code が「このフォルダを信頼するか」を聞く（既定は「No, exit」）。アプリは答えないので、画面に出たターミナルで自分で答える。
チームメイトを置けるのは、リーダーが動いている PC（環境 `local`）だけ。
ほかの環境のリポジトリは、リーダーも読める。ただ、チームメイトは置けず、頼んでも何も作らずに断る（SendMessage が同じ PC の中でしか届かないため）。
その PC のチームメイトの記録は、その PC に置かれる。つなぎAI は、その PC のサーバーにつないで読み、流れに出す。
閉じたチームメイトの記録を消すのも、そのサーバーにたのむ。
リーダーが PC で動く前に作ったフォーメーションのチームメイトが、この Mac の記録に残っているときは、それも同じフォーメーションのチームメイトとして出し、閉じ、削除する。
中のペインには、チームメイトのタブと同じように、そのターミナルを出す（Orca の画面がその接続先をストリームしていればストリーム、していなければミラー）。
再起動のボタンは、そのターミナルを閉じて作り直す。

#### その PC のサーバー

Orca に保存した接続先のフォーメーションでは、その PC のチームメイトの記録を読むために、つなぎAI がその PC に `tsunagiai-mcp` を置き、サーバーとして動かす。
Orca のファイルの読み出しは、Orca に登録したフォルダの中しか読めず、つなぎAI の設定フォルダは読めないためである。
置くのは、つなぎAI と同じ版の `tsunagiai-mcp` だけ。
その PC の Orca のターミナルで、GitHub の Release からダウンロードして取り出し、つなぎAI の署名と同じものかを確かめてから、設定フォルダの `remote/` に置く。
置けるのは、署名したつなぎAI の、リリースした版だけ（開発版は置けない）。macOS（Apple Silicon）の PC だけに置ける。
サーバーは、その PC に届く IP アドレスの、ポート 47823 で待ち受ける。Orca の接続先が名前で指定されているときは、置けない。
つなぎAI とサーバーは、お互いの鍵を固定して、暗号化した WebSocket でつなぐ。
つなぎAI の秘密の鍵は、キーチェーンに入れる。
サーバーが答えるのは、版、フォーメーションの記録を読むこと、閉じたチームメイトを記録から消すこと、止めることだけ。
起動の登録（launchd）はしない。リーダーの起動のときに起動し、つながらなければ、つなぎAI が一度だけ起動する。
版が違えば、つなぎAI が置き直す。
起動や置き直しの間、画面の読みはそれを待たず、「その PC のサーバーを起動しています」のように理由を出して、次の読みに任せる。
その PC のファイアウォールが新しいプログラムを止めているときは、最初の起動のときにその PC の画面に出る確認で「許可」を押す。

#### その PC への同意

その PC に置くことには、PC（Orca に保存した接続先）ごとに、一度、あなたの同意が要る。
その PC のプロジェクトでフォーメーションを初めて作るとき、置くものを示して聞く。同意しなければ、フォーメーションは作らない。
同意の前に作ったフォーメーションは、そのリーダーを起動するときに聞く。
同意は、設定の Orca タブの「サーバーを置いた PC」に出る。
「取り消す」を押すと、その PC のサーバーを止め、置いたプログラムを消して、同意をなくす。
その PC のフォーメーションが残っているときは、取り消せない。先に削除する。
Orca から接続先が消えているときは、その PC には何もせず、同意だけをなくす。
起動のしかたと、渡すツールは [Claude](claude-integration.md#開発の画面のリーダーで-claude-code-を動かす) にある。

### チームメイト

チームメイトは、リーダーと同じ PC（この Mac か、Orca に保存した接続先）の、リーダーが選んだリポジトリに作った新しい worktree か、そのリポジトリにある既存のフォルダのターミナルで動く Claude Code（auto モード、effort は medium）。
worktree は、そのリポジトリの `.claude/worktrees/` の下（`.claude/worktrees/{リポジトリ}/{チームメイトの名前}`）に作る。フォーメーションを作るときとチームメイトを起動するときに、Orca のそのリポジトリの worktree の場所を `.claude/worktrees` にする（Orca のほかの設定は変えない）。
この設定はリポジトリのものなので、そのリポジトリで「Orca に渡す」や作業ペインの＋で作る worktree も、以後は同じ場所にできる。
この Mac のリポジトリでは、git の `info/exclude` に `/.claude/worktrees/` を足し、`git status` に出さない（`.gitignore` は変えない）。保存した接続先のリポジトリには書かない。
リーダーは、指示の目的を果たし、仕事を終わらせるまで進める。
指示を受けたら、まず自分で調べ、目的、ゴール、計画（チームメイトの数、役割、置き場所、順番）を決める。決めたことはあなたに短く伝え、承認を待たずに進める。
あなたが言ったプロジェクトがどの環境のどのリポジトリかも、自分で確かめる。一つに決められないときだけ、あなたに聞く。
リポジトリの worktree の一覧、フォルダの中、ファイルの中身、git の状態とブランチを、読むだけで確かめる（どの環境のリポジトリでも同じ）。
読めるのは、リポジトリの本体のフォルダと、Orca が一覧に出す worktree だけで、その外のパスは断る。
`.git` の中と、`.env` で始まる名前のファイルは、一覧に出さず、読むことも断る。ファイルは 2,000 行ずつ読み、続きは行の位置を渡して読む。
チームメイトのブランチは、リーダーが渡さなければ Orca が決める。渡すときは、git が受け付ける名前なら形は問わない（`-` で始まる名前は断る）。
worktree は Orca に頼んで作る。この Mac のリポジトリでも、保存した接続先のリポジトリでも、同じように決まる。
そのリポジトリにあるブランチは、そのまま開く（ローカルのコミットのまま）。
`origin` にだけあるブランチ（前のチームメイトが push して閉じたブランチ）は、`origin/{ブランチ}` から同じ名前で切る。
どこにも無い名前は新しいブランチで、リーダーが起点（`base`）を渡せばそこから、渡さなければ Orca の既定（ふつうは `origin/HEAD`）から切る。
Orca が `{ブランチ}-2` のような別の名前で作ることはない。
別の worktree が開いているブランチや、使われている名前は、Orca が断り、その言葉をそのままリーダーに返す。何も作らず、リーダーは別の置き場所やブランチを選び直す。
リーダーは、worktree を作らずに、そのリポジトリの本体のフォルダか、Orca が一覧に出す worktree を渡して、チームメイトをそこで動かすこともできる。
このとき、何も作らない。Orca の一覧にないフォルダと、別のリポジトリのフォルダは断る。ブランチとフォルダを一緒に渡すことも断る。
リーダーは、チームメイトに SendMessage で指示し、チームメイトは仕事が終わったときと判断が要るときにリーダーに知らせる。
チームメイトの質問には、リーダーがまず自分で調べて答える。
あなたに聞くのは、資料で決まらない製品や仕様の判断、取り消せない操作（force push、履歴の書き換え、本番への書き込み、公開）、調べても決まらず目的が変わることだけで、調べたこと、選択肢、推奨を添えて文章で聞く。
リーダーは、ゴールに届いたかを自分で確かめてから、結果をあなたに報告する。
チームメイトの仕事が終わっても、リーダーは自分では閉じない。終わったチームメイトの worktree とタブは、あなたが閉じるまで残る。
リーダーが閉じるのは、あなたがはっきり頼んだときだけで、閉じる前に push してもらう。
閉じると、チームメイトのターミナルを閉じ、worktree を消す。ブランチも、つなぎAI が作ったものなら消す。worktree を作る前からそのリポジトリにあったブランチは、消さない。
その worktree の中で、既存のフォルダとして動くチームメイトがいる間は、worktree を消さない（そのチームメイトを先に閉じる）。
コミットしていない変更、追跡していないファイル、どのリモートにも無いコミットがある worktree は消さず、理由を伝える。
既にあったフォルダで動かしたチームメイト（つなぎAI が作っていないフォルダのチームメイト）は、終えても、ターミナルを閉じて記録から外すだけにする。フォルダも worktree もブランチも消さず、変更やコミットがあっても止めない。
保存した接続先のチームメイトは、その接続先の Orca で確かめる。確かめられないとき（追跡するリモートのブランチが無いときを含む）は消さない。
Orca から接続先を消していれば、そのチームメイトは何も消さずに記録から外す。
Orca で worktree を先に消していれば、記録から外すだけで、同じ名前のチームメイトをまた起動できる。

### feature-dev で機能を作る

リーダーに `feature-dev` と打つと、リーダーが機能の開発を、要件定義、基本設計、実装（リポジトリごとに 1 つ）、仕様書の順に、工程ごとのチームメイトに任せる。
打つときに、指示を続けてもよい。続けなければ、記録の続きから進める。
リーダーは作業をしない。工程のチームメイトを一人ずつ起動し、その返事を受け、記録（ドキュメント用のリポジトリの `.feature-dev/current/case.json`）で完了を確かめてから、次の工程に進む。
工程の間で、続けてよいかをあなたには聞かない。あなたの判断と承認は、チームメイトの判断ページ（[判断ページ](#判断ページ)）で受ける。
ドキュメントとブランチは、はじめに決める。あなたの言葉に無ければ、リポジトリの決まりを読み、決められないときだけ聞く。
チームメイトを置けるのは、これまでと同じく、リーダーが動く PC（環境 `local`）のリポジトリだけ。
リーダーの skill と、チームメイトのプラグイン（工程ごとの手順書と、7 つの agent）は、アプリに入っている。
リーダーの起動のたびに、リーダーのフォルダの `.claude/skills/feature-dev/` を、skill の全体で置き換える（そこにある、ほかの skill は変えない）。
保存した接続先のフォーメーションのリーダーにも、同じように書き出す。
プラグインは、チームメイトを起動するときに、その PC の設定フォルダの `formation-plugin/` に書き出す。中身が同じなら、書き直さない。
Claude Code のチームメイトは、このプラグインを付けて起動する（Codex のチームメイトには付けない）。
文章の推敲に使う `yomiyasu` と `natural-japanese` は、リーダーが、最初のチームメイトを起動する前に、入っているかを確かめ、無ければユーザーのスコープに入れる。
`yomiyasu` を入れられないときは、判断ページが通らないので、リーダーが理由を伝えて止まる。`natural-japanese` を入れられないときは、それ無しで進める。

### Codex のチームメイト

チームメイトは、Claude Code のほかに Codex でも動かせる。
リーダーのツール `formation_launch` と `formation_plan` の `agent` に、`claude`（既定）か `codex` を渡す。
Codex のチームメイトは、Claude Code と同じ worktree かフォルダの、同じ Orca のターミナルで、`codex --sandbox workspace-write --ask-for-approval never` を動かす。
ターミナルの題は、チームメイトの名前になる。プラグインは付けない。
`codex` が入っていない PC と、ログインしていない PC では、ターミナルが入力を受けないまま止まり、起動は「子のエージェントの立ち上がり待ち」で失敗する。入っているかとログインしているかを確かめるよう、理由に出る。
そのチームメイトは記録に残るので、リーダーが閉じられる。
Codex のチームメイトのタブには、effort の代わりに `codex` の札が付き、カードの名前のあとにも `codex` と出る。Claude Code のチームメイトのカードには、札は付かない。
状態は、Orca のセッションの一覧にその行がないので、ターミナルの一覧で決める。
ターミナルが、チームメイトの worktree かフォルダの下に一覧にあれば作業中で、なければ完了（ターミナルのタブは出さない）。
承認待ちには、ならない。承認の方針が「求めない」で、Orca は Codex の 1 回ごとの動きを知らせないため。
別のパスの下に出ているターミナル（あなたのターミナルや、リーダーのターミナル）は、そのチームメイトのものとは見なさず、閉じない。
Codex には SendMessage が届かない。Codex のチームメイトは、結果を、リーダーが指したファイルに書き、最後に空の `{そのファイル}.done` を置いて知らせる。
リーダーは、その `.done` が置かれるのをディスクで待ち、結果を読んで、頼んだチームメイトに渡す。
工程のチームメイトが頼む Codex のレビューは、この渡し方で行う。

### 流れ

右の「流れ」は、幅 260px の縦一列のカードで、フォーメーションを選んでいる間は、いつも出す（チームメイトがまだいないときは、リーダーのカードだけを出す）。
見出しの右端に「自動で追う」のアイコンがある。
いちばん上がリーダーのカード（フォーメーションの名前と「リーダー」の札）で、その下に、線でつないで、チームメイトのカードを一列に並べる（縦に収まらないときは、カードの列だけが縦にスクロールする）。
起動したチームメイトのカードには、起動した順に、名前、状態が続いている時間、状態（作業中、承認待ち、完了）、最後の返事の 1 行目を出す。色は Orca と同じ。
リーダーが予定に入れただけのチームメイトは、点線の枠で「予定」と出し、起動すると同じ場所で普通のカードになる。
カードを押すと、中のペインがそのチームメイトのタブ（リーダーのカードなら、リーダーのタブ）に切り替わる。
チームメイトのカード（予定のチームメイトも）を右クリックして「削除」を押すと、確かめてから、リーダーが閉じるときと同じようにチームメイトを閉じる。
完了したチームメイトのカードの × も、同じ確かめのあとで閉じる。
つなぎAI が作っていないフォルダのチームメイトの確認は、ターミナルを閉じて一覧から外すだけで、フォルダ、worktree、ブランチは消さないと言う。
閉じられないときは、理由と、変更のあるファイル、追跡していないファイル、どのリモートにも無いコミット、worktree の場所を出す。
そこで「強制削除」を押すと、出した worktree を消す。変更と追跡していないファイルは失われ、どのリモートにも無いコミットはローカルのブランチに残す（残したブランチはカードの上に出す）。リーダーは強制では閉じない。
フォーメーションを選んでいる間、3 秒ごとに読み直す。読み込めなかったときは、カードの上に理由を出し、前のカードを残す。

### チームメイトのタブ

中のペインの上にタブ列がある。
先頭がリーダーのタブ（札は「high」）で、そのあとに、カードと同じ順で、チームメイトのタブが並ぶ（札は「medium」）。長いときは、タブ列だけが横にスクロールする。
タブには状態の印が付く。◐ は作業中、● は承認待ち（リーダーのタブでは入力待ち）、✓ は完了、○ は予定。
完了したチームメイトのタブには × が付き、あなたが押すまで残る（チームメイトの worktree も、そのときまで残る）。
予定のチームメイトのタブは点線の枠で出る。予定のチームメイトと、ターミナルを閉じた完了のチームメイトのタブは、押しても何も選ばない。
タブかカードを押すと、そのターミナルを出してキーの入力を移す。
ターミナルにはそのまま打ち込め、チームメイトの承認や質問にここで答えられる。
Orca の画面がストリームで見せている保存した接続先のチームメイトは、Orca の画面と同じくストリームで出す。色が付き、ターミナルが中のペインの大きさに合う。別のタブを選ぶと、ストリームを閉じ、元の大きさに戻す。
ほかのチームメイト（この Mac のチームメイトと、ほかの保存した接続先のチームメイト）は、画面を Orca から読んで写す（色は付かない）。
「自動で追う」を入れると、読み直すたびに、いちばん長く承認を待っているチームメイト、なければ選んでいる作業中のチームメイトか最初の作業中のチームメイトのタブに移り、そのカードを見える所に出す。移ってもキーの入力は移らない。
タブかカードを押すと切れ、アイコンを押すとまた入る。「自動で追う」は、アプリを起動したときと、フォーメーションを開いたときは切れていて、中のペインはリーダーのタブのままになる。

### 判断ページ

判断や承認がほしいチームメイトは、あなたへの質問や承認を、判断ページにする。
チームメイトがページを書き、リーダーが `formation_page` に渡すと、アプリがページを調べて、そのチームメイトの待ちにする。
ページは 3 種類で、要件定義と基本設計の論点、要件定義と基本設計の承認、実装のコードレビューがある。
入力の形が違うとき、ページが指すファイルがリポジトリの外にあるとき、見つからないときは、直すところを全部並べて断る。リーダーがそれをチームメイトに返し、チームメイトが直して出し直す。
ページの日本語の文は、`yomiyasu` で推敲した記録にあるものだけを通す。無い文があるときは、その文を並べて断り、チームメイトが推敲し直してから出し直す。
ページが通ると、次のようになる。

- 待っているチームメイトのカードに、状態の代わりに「判断待ち」（承認を待つときと同じ色）と、ページの題が出て、すぐ横にボタン「開く」が付く。カードを押すと、これまでどおりそのターミナルが出る。
- タブ列の、そのチームメイトのタブのすぐ右に、「判断: {題}」のタブが付く。印は、待っているチームメイトと同じ。待ちがないチームメイトには、どちらもない。
- 「開く」かそのタブを押すと、中のペインに、ターミナルの代わりにそのページが出る。リーダーやチームメイトのタブ、カードを押すと、ターミナルに戻る（ページは残る）。ページを出している間は「自動で追う」が切れ、入れ直すと、待っているチームメイトに移ってページを隠す。
- ページは、タブを初めて出すときと、チームメイトが出し直したとき（待ちの時刻が変わったとき）に読み直す。3 秒ごとの読み直しでは、読まない。読めなかったときは、理由（直すところを 1 行ずつ）をページの代わりに出し、タブをもう一度押すと読み直す。
- 待ちが消えたページは、タブを閉じ、その前に選んでいたタブを出す。別のフォーメーションを選ぶと、ページはすべて忘れる。ページに入れた答えは、タブを出していない間も残る。

ページに出るのは次のとおり。

- 題と、文脈、「{チームメイト} から」。
- 「何が変わるか」（要約と、変更の部分。承認では畳み、コードレビューでは開く）。
- 承認では「リスク・リリース上の注意」（根拠は「根拠を見る」の中）と「承認の対象」（対象ごとに、中身は「中身を見る」の中）。
- カードの組。論点、判断が必要、未解消の必ず直す指摘、構造改善の提案、ADR（設計判断の記録）、満たしていないリリース条件が、それぞれ見出しに「{名前} {件数} 件」を付けて並ぶ。
- 「参考」の下に、決まったこと（仮のものは印が付く）、品質の確認の結果、プルリクエスト、前の返事。

カードには、番号、題、要約があり、図があれば最初の 1 つを出す。
背景、事実、ブロック（段落、見出し、表、変更前と変更後、図など）、根拠（ファイルの抜粋、差分、git の差分、記録の JSON の部分）は、「詳しく見る」の中に出す。
図は Mermaid で描く。描けないときは、元の文を出す。ページの文は、すべて文字のまま出し、HTML としては読まない。
選ぶ欄は、カードの種類で決まる。

- 論点と、判断が必要なカード（要件定義と基本設計の判断、コードレビューの判断）は、ラベルの付いた選択肢をラジオで出す。推奨は A で、印と理由が付き、選択肢の詳しい説明は「この選択肢の詳細」の中。そのあとに、「調べてから決めて」「今回は対応しない」「その他」が並び、「その他」を選んだときだけ、自由に書く欄が出る。
- 未解消の必ず直す指摘は「指摘のとおり修正する」か「今回は対応しない」、構造改善の提案は「承認」「却下」「保留」、ADR は「残す」「不要」、コードレビューの必ず直す指摘は「修正して再レビューする」か「現状で完了する」を選ぶ。選択肢の下に、補足の欄がある（構造改善の提案では「理由（却下・保留のとき）」、そのほかは「補足（任意）」）。
- 満たしていないリリース条件には、答える欄がない。
- 「選択を取り消す」で、カードの選択を戻せる。はじめは何も選んでいない。

ページの終わりのボタン「リーダーに送る」で、答えを送る。
アプリは、ページを読み直して（根拠は読まない）、答えから返信の文を作る。
承認とコードレビューでは、1 行目が承認か修正の依頼の文になり、そのあとに、答えのあるカードが、ページの順に「{番号} {題}」、答えの行、「補足: …」で並ぶ。
答えが要るカード（論点と、承認の必ず直す指摘）に答えがないときは、送らず、「回答が必要なカードが未回答です: {番号}」と出す。
返信の文は、「判断ページの返信（{チームメイト}）」の行に続けて、リーダーのターミナルに打ち込む（貼り付けとして 1 回で入れてから、少しあとに Enter を打つ。制御文字は取り除く）。保存した接続先のフォーメーションでは、その PC の Orca のリーダーのターミナルに送る。
リーダーは、その返信を、そのままチームメイトに返す。
送れたら、ページのタブを閉じ、カードはまた状態を出す。
送れなかったとき（リーダーが動いていない、Orca が答えない、ページが差し替わった）は、ページと答えをそのまま残し、ボタンの下に理由を出す。ボタンは、また押せる。
返信を送ってから、そのページの印を付けられなかったときは、次に押したときは印を付けるだけで、返信は送り直さない。
