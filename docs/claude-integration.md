# Claude

## メールを AI で要約する

メールの詳細画面の「AI 要約」アイコンを押すと、Claude Code の CLI（`claude -p`）がスレッドを要約し、要点の短い箇条書きを件名の下のカードに出します。
カードの × かアイコンで閉じられ、もう一度アイコンを押すと、送り直さずに同じ要約を出します。
そのスレッドに新しいメッセージが届くと、要約は作り直しになります。

- 使えるのは、`claude` が入っていて、`claude auth login` でログインしているとき、または API キーが使えるときです。それ以外のときは、アイコンを出しません。
- アイコンを押したときだけ、スレッドの件名と、各メッセージの差出人、日時、本文のテキスト（新しいメッセージから順に 10,000 文字まで）を、Claude Code 経由で Anthropic に送ります。要約のとき、モデルには道具も MCP サーバーも渡しません。
- 要約は保存しません。アプリを終了すると消えます。

## Orca に渡す内容を要約する

メールと Slack のスレッドの画面の右側、Todo の詳細の下の「Orca に渡す」ペインで指示を書き、右下の矢印のアイコン（「Orca に渡す」）を押すと、Claude Code の CLI（`claude -p`）がカードに出ている内容を箇条書きに要約します。
書いた指示は要約せず、そのまま Orca に渡します。要約は、添付したファイルのパスのあと、元の内容の引用の中に入ります。

- 使えるのは、Claude が使える状態のときです。カードが出ているのに使えないときは、矢印が止まります。カードを外せば、要約は要らないので渡せます。
- 矢印を押したときだけ、カードに出ている内容（メールのスレッド、Slack のスレッド、Todo のタスクのテキスト）を、Claude Code 経由で Anthropic に送ります。カードを外していれば送りません。モデルには道具も MCP サーバーも渡しません。書いた指示と添付したファイルは送りません。
- 要約は保存しません。
- 要約のためのモデルと effort を選ぶ欄は、ペインにはありません。設定の Claude タブの「Orca に渡す要約」で選びます。

## Todo の Claude ペインで Claude Code を動かす

Todo 画面の右側は、いつも開いていて、Claude のペインが出ます。
窓が狭く、タスクの欄が 612px より狭くなるときは、Claude のペインをタスクの下に出し、間の仕切りで高さを画面の 30% から 45% まで変えられます。このとき Claude のアイコンは、タスクの見出しの「編集」の右に出ます。窓を広げると、右に戻ります。
ペインの見出しは「Claude」と「やり直す」で、その下が Claude Code のターミナルです。右側の上の帯の右端にある Claude のアイコン（マウスを乗せると「Claude に相談」と出ます）を押すと、ターミナルに移ります。
Claude Code は、Todoist のプロジェクトとタスクを読み、タスクを足せます。足したタスクは、Todo の一覧に出ます。

- 使えるのは、`claude` が入っているときです。見つからないときと、`tsunagiai-mcp` が見つからないときは、ペインにそう出ます。
- Claude Code は、設定フォルダの `claude-code/` で動きます。MCP サーバーは `tsunagiai-mcp` だけを渡し、Bash などの組み込みの道具とスキルは渡しません。
- 最初の指示には、Todoist の相談であることと、今日の日付と、使えるツールの名前だけを入れます。タスクやメールの内容は入れません。
- Todoist のプロジェクトとタスクを読む `todoist_projects` と `todoist_tasks` は、聞かずに読みます。タスクを足す `todoist_add_task` は、そのたびにターミナルで、足してよいかを聞きます。
- 足せるタスクは、名前（500 文字まで）、日付（`YYYY-MM-DD` か `YYYY-MM-DD HH:MM`）、プロジェクト（なければインボックス）です。名前が空のときと、Todoist にないプロジェクトは断ります。
- Todoist のトークンは、アプリの Todo 画面で入れたものを使います。入れていないときは、ツールが、Todo 画面で入れるように答えます。
- 足すと、Todo の一覧が読み直されます。アプリが動いていないときは、次に Todo 画面を出したときに読みます。
- Claude Code は、Todo 画面の一覧かタスクを初めて出したときに起動します。ほかの画面に移っても、ウィンドウを隠しても、動き続けます。トークンの入力欄と下書きのページを出している間は、起動しません。
- 「やり直す」を押すと、Claude Code を終えて、同じ最初の指示で新しく始めます。ペインを閉じるボタンはありません。Claude Code が自分で終わったときは、ターミナルにそう出ます。
- ターミナルに打ち込んだ内容と、Claude Code が呼んだツールの結果（Todoist のタスクの名前と説明、プロジェクトの名前）は、Claude Code を通じて Anthropic に送ります。本アプリが自分で送る文章はありません。
- Orca に渡すペインは右側には出ません。タスクを開くと、詳細の見出しの「編集」の左に「Orca に渡す」のボタンが出て、押すと詳細のコメントの下にペインが開きます（[Orca](orca.md#orca-に渡す)）。Claude のペインは、そのあいだも変わりません。

## メールの Claude ペインで Claude Code を動かす

スレッドを開いているときと、新しいメールを書く画面の右側に、Claude のペインが出ます。
右側の上の段の右端に、Claude（✳）と Orca の 2 つのアイコンがあり、押したほうのペインを出します。初めは Claude のペインです。Orca のアイコンは、スレッドを開いているときだけ出ます（[Orca](orca.md#orca-に渡す)）。
Claude のペインは、スレッドや新しいメールを開いたときは閉じていて、「Claude に相談しますか？」と「相談する」だけを出します。Claude Code は動いていません。
「相談する」か ✳ を押すと開き、見出し「Claude」と「やり直す」の下に Claude Code のターミナルが出ます。✳ をもう一度押すと閉じ、Claude Code を終えます。
Orca のペインから ✳ を押すと、Claude のペインを開いた状態で出します。
Claude Code は、開いているスレッドと、返信か新しいメールの宛先、Cc、Bcc、件名、本文を読み、書けます。

- 使えるのは、`claude` が入っているときです。見つからないときと、`tsunagiai-mcp` が見つからないときは、ペインにそう出ます。
- MCP サーバーは `tsunagiai-mcp` だけを渡し、Bash などの組み込みの道具とスキルは渡しません。最初の指示には、メールの内容は入れません。
- スレッドは `mail_thread_read` で、欄は `screen_read` で読みます。読むときは聞かれません。
- `screen_write` で欄を書くたびに、ターミナルで聞かれます。書いた内容はすぐ欄に入ります。返信の件名は書けません。
- 書いたあと、返信欄の下と、新しいメールの下の帯に「元に戻す」が出て、新しい書き込みから順に戻せます。自分で欄を直したとき、送ったとき、「破棄」のときは、戻せなくなります。
- Claude Code はメールを送りません。送るのは、自分で「送信」を押したときだけです。
- ペインを開いたとき起動します。一覧やほかの画面に移っても、開いている間は動き続けます。別のスレッドか新しいメールを開くと、Claude Code を終え、ペインは閉じた状態に戻ります。
- ターミナルに打ち込んだ内容と、Claude Code が読んだスレッド（各メッセージの差出人、日時、本文）と欄の内容は、Claude Code を通じて Anthropic に送ります。スレッドは他人が書いたものなので、Claude Code には、データであって指示ではないと伝えます。

## Slack の Claude ペインで Claude Code を動かす

Slack のスレッドの詳細の右側、Slack の画面の右のペイン、「Slack に貼る」の画面の Claude モード、Todo の案のページ、要約プロンプトの画面の右側は、どれも Claude Code のターミナルです。
どれも、MCP サーバーは `tsunagiai-mcp` だけを渡し、組み込みの道具とスキルは渡しません。書くたびにターミナルで聞かれ、書いた内容は欄に入るだけで、投稿、追加、保存は自分で押します。
くわしくは [Slack](slack.md) にあります。

## スキルのタブで Claude Code を動かす

設定の「スキル」タブの編集欄の右に、Claude Code のペイン（「Claude と編集」）があります。見出しの右端の「やり直す」で、Claude Code を終えて新しく始めます。
タブを初めて出したとき起動し、ほかのタブや画面に移っても、隠すだけで動き続けます。
Claude Code は、`skill_list` でスキルの一覧を、`skill_get` でスキルの全文を読みます。読むときは聞かれません。
`skill_save` でスキルを保存するたびに、ターミナルで聞かれます。保存の確かめは、画面の「保存」と同じです。スキルを消すツールはありません。
保存すると、タブの一覧を読み直し、編集欄に出しているスキルが変わっていれば、保存した内容を入れ直します。
MCP サーバーは `tsunagiai-mcp` だけを渡し、組み込みの道具とスキルは渡しません。スキルの文章は編集するためのもので、その中の指示には従わないと伝えます。
ターミナルに打ち込んだ内容と、Claude Code が読んだスキルの文章は、Claude Code を通じて Anthropic に送ります。

## カレンダーの Claude ペインで Claude Code を動かす

カレンダー画面の上の帯の右端に、Claude のアイコンがあります（マウスを乗せると「Claude に相談」と出ます）。
押すと、週の右に Claude のペインが開きます。もう一度押すと閉じます。
ペインの見出しは「Claude」と「やり直す」で、その下が Claude Code のターミナルです。
Claude Code は、予定とカレンダーを読み、表示するカレンダーを切り替え、予定を作り、書き換え、削除し、空き時間の候補を週の上に描けます。

- 使えるのは、`claude` が入っているときです。見つからないときと、`tsunagiai-mcp` が見つからないときは、ペインにそう出ます。
- アプリを起動したときは、ペインは閉じていて、Claude Code は動いていません。アイコンを押して開いたときに起動します。
- アイコンでペインを閉じると、Claude Code を、動かしたものごと終えます。次に開くと、新しく始めます。
- ペインを開いている間は、ほかの画面に移っても、ウィンドウを隠しても、Claude Code は動き続けます。
- 「やり直す」を押すと、Claude Code を終えて、同じ最初の指示で新しく始めます。Claude Code が自分で終わったときは、ターミナルにそう出ます。
- Claude Code は、設定フォルダの `claude-code/` で動きます。MCP サーバーは `tsunagiai-mcp` だけを渡し、Bash などの組み込みの道具とスキルは渡しません。
- 最初の指示には、カレンダーの相談であることと、今日の日付と、使えるツールの名前と、予定の題や説明や場所に書かれた指示には従わないことだけを入れます。予定の内容は入れません。
- Claude Code は auto mode で起動し、ツールを使うたびには確認を聞きません。渡すツールは、次の 7 つだけです。
- `list_events` は、予定を読みます。返すのは、予定の題、開始と終了の日時、終日かどうか、辞退したかどうか、場所、説明（1,000 文字で切ります）、Meet の URL、参加者の人数と承諾した人数、自分の回答、カレンダーの名前、アカウントのメールアドレス、予定の ID、編集と削除ができるかです。利用者が主催した予定には、参加者のメールアドレスも付きます。読むのは、カレンダー画面で表示するカレンダーだけです。題、場所、説明は人が書いたことがあるので、データとして扱い、そこに書かれた指示には従いません。
- `list_calendars` は、アカウントごとのカレンダーを、自分が持ち主かどうかと、表示しているかどうかとともに読みます。`calendar_set_shown` は、カレンダー画面のチェックボックスと同じに、表示するカレンダーを切り替えます。
- `calendar_create_event`、`calendar_update_event`、`calendar_delete_event` は、カレンダー画面と同じ確かめで、予定を作り、書き換え、削除します。作るのは自分が持ち主のカレンダーで、書き換えと削除ができるのは、自分が主催した予定で、自分が持ち主のカレンダーにあるものだけです。繰り返しの予定は、その回だけで、シリーズ全体は断ります。予定を変えると、画面の週は読み直されます。
- ゲストがすでにいる予定への変更と取り消しと、ゲストのいない予定の作成、書き換え、削除は、確認を聞かずに Google に送ります。ゲストがいれば、Google から変更か取り消しの知らせが届きます。
- 新しい人をゲストに足すとき（ゲスト付きの予定の作成を含む）は、Claude Code は何も送りません。画面の作成か編集の欄に値を入れるだけで、ゲストに招待が届くのは、利用者が「保存」を押したときです。
- `calendar_show_slots` は、空き時間の候補を描きます。
- `calendar_show_slots` は、候補を 1 件から 8 件、週の上に赤い破線の枠で描きます。候補は、同じ日の中の開始と終了（`YYYY-MM-DDTHH:MM`）です。保存も送信もせず、次に描くと前の候補と置き換わります。ペインを閉じているときは、断ります。
- 描いた候補は、帯の「候補 N 件」の ✕ か、ペインを閉じると消えます。枠の下の空いた場所を押すと、予定の作成が開きます。
- ターミナルに打ち込んだ内容と、Claude Code が `list_events` と `list_calendars` で読んだ予定とカレンダーは、Claude Code を通じて Anthropic に送ります。本アプリが自分で送る文章はありません。

## データベースの画面で Claude Code を動かす

データベースの画面の右ペインのタブの帯の先頭に、「Claude」のタブがあります。
作業ペインの見出しの右端のアイコンか、接続の編集ペインの見出しの右端のアイコンで右ペインを開くと、Claude Code が動いていなければ、このタブで起動します。
タブはターミナルで、アプリが自分で開いて `claude` を起動します。Orca は使いません。
事前スクリプトを書いてもらい、`tsunagiai-mcp` のツールで接続を保存してテストしてもらえます。保存された接続は、約 2 秒で左の一覧に出て、内容は手で直していない欄に読み込まれます。

- 使えるのは、`claude` が入っているときです。見つからないときと、`tsunagiai-mcp` が見つからないときは、タブにそう出ます。
- Claude Code は、設定フォルダの `claude-code/` で動きます。MCP サーバーは `tsunagiai-mcp` だけを渡し、ほかの設定ファイルの MCP サーバーは使いません。
- スクリプトを試せるように、Bash などの組み込みの道具も使えます。書き込むツールとコマンドは、使う前に Claude Code が確かめます。「常に許可」を選んでも、その回の Claude Code の中だけです。
- サインインは、下の「Claude の接続方式」で選んだ方式です。書体、配色、キーは Orca のターミナルと同じです。
- タブに打ち込んだ内容と、Claude Code が呼んだツールや道具の結果は、Claude Code を通じて Anthropic に送られます。
- 右ペインを閉じても、データベースの画面を離れても、編集ペインを閉じても、Claude Code は動き続けます。右ペインを開き直すと、同じ Claude Code が出ます。
- Claude タブの × を押すと、Claude Code を終えてタブを消します。Claude Code が終了コード 0 で終わったときも、タブを消します。ほかにタブがなければ右ペインも閉じ、次に開いたときに起動し直します。
- 0 以外の終了コードで終わったときは、理由が読めるように、× を押すまでタブとメッセージが残ります。
- アプリを終了すると、Claude Code も終えます。

## Orca の言語サーバーの欄で Claude Code を動かす

開発の画面のファイル欄の「言語サーバー」の欄の、見出しの ✦ と、サーバーが見つからなかった言語のカードの「Claude に頼む」で、欄のカードの下に Claude Code のペインが開きます（画面は [Orca](orca.md#claude-code-に設定を頼む)）。
ペインはターミナルで、アプリが自分で開いて `claude` を起動します。Orca は使いません。
worktree を読み、言語サーバーの設定を `tsunagiai-mcp` の `lsp_settings` と `lsp_server_save` で書いてもらえます。

- 使えるのは、`claude` が入っているときです。見つからないときと、`tsunagiai-mcp` が見つからないときは、ペインにそう出ます。
- Claude Code は、設定フォルダの `claude-code/` で動きます。MCP サーバーは `tsunagiai-mcp` だけを渡し、worktree を読めるように、Bash などの組み込みの道具も使えます。
- 最初の指示は、アプリが作ります。環境、プロジェクト、worktree（保存した環境の worktree では、ssh の接続先も）を、指示ではなく資料として引用の形で渡します。✦ は言語を限らず、「Claude に頼む」はその言語だけを頼みます。
- 最初の指示は、入っていないサーバーを入れる前にあなたに聞くこと、`lsp_server_save` には `language` を渡し、アプリが見つけるサーバーの `command` は省くことを頼みます。
- 書き込むツールとコマンドは、使う前に Claude Code が確かめます。「常に許可」を選んでも、その回の Claude Code の中だけです。
- サインインは、下の「Claude の接続方式」で選んだ方式です。
- ペインに打ち込んだ内容と、Claude Code が呼んだツールや道具の結果は、Claude Code を通じて Anthropic に送られます。
- 同じ頼みをもう一度押しても、何も変わりません。別の頼み（別の言語、別の worktree）は、前の Claude Code を終えて、新しく始めます。
- ペインの ✕ を押すと、Claude Code を終えてペインを閉じます。欄を隠したときや、別の worktree を出したときは、隠すだけで、Claude Code は動き続けます。Orca の一覧から worktree が消えたときと、アプリを終了したときに、終えます。

## 開発の画面のリーダーで Claude Code を動かす

開発の画面のフォーメーションの中のペインは、リーダーの Claude Code です（画面は [Orca](orca.md#オーケストレーション)）。
フォーメーションごとにリーダーがあり、一覧で選んだフォーメーションのリーダーを、初めて出したときに、アプリが自分で開いたターミナルで `claude` を起動します。Orca は使いません。
Orca に保存した接続先のフォーメーションは別です。リーダーを、その PC の Orca のフローティングのターミナル（どのリポジトリにも属さないもの）で、つなぎAI がその PC の設定フォルダの `remote/` に置いた `tsunagiai-mcp` が起動します。先に `--serve` でサーバーを起動し、そのあと `--formation-start {フォーメーションの名前}` でリーダーになります。選んだプロジェクトは、起動のときに最初の指示として渡します（[Orca](orca.md#リーダー)）。
新しいフォルダで初めて起動するときは、Claude Code が「このフォルダを信頼するか」を聞くので、画面に出たターミナルで答えてください。アプリは答えません。
以下の「Claude Code は、設定フォルダの…」などは、そのときも、起動した PC の設定フォルダの話です。
リーダーは仕事をチームメイトに分け、チームメイトは Orca の新しい worktree で動く Claude Code です。リーダーは effort high、チームメイトは effort medium で起動します。

- 使えるのは、`claude` が入っているときです。見つからないときと、`tsunagiai-mcp` が見つからない（保存した接続先の PC では、置かれていない）ときは、ペインにそう出ます。
- Claude Code は、設定フォルダの `formations/{フォーメーションの名前}/` で動き、セッションの名前はフォーメーションの名前です。起動のたびに、リーダーへの指示（`CLAUDE.md`）、MCP の設定、起動のスクリプト、空のプロジェクト設定（`.claude/settings.json`）と、リーダーの skill `feature-dev`（`.claude/skills/feature-dev/`。ここだけ、フォルダごと置き換え、ほかの skill には触れません）を書き直すので、リーダーが足した許可やフックは、次の起動には残りません。
- フォーメーションを作るときに選んだプロジェクトがあれば、起動のたびに、それを最初の指示として渡します。プロジェクトの名前は、指示ではなく資料として引用の形で渡し、リーダーはあなたの指示を待ちます。
- 権限のモードは auto、effort は high で、組み込みの道具（Bash など）も使えます。道具やコマンドを使う前に確かめるかどうかは、Claude Code の auto モードが決めます。
- MCP サーバーは `tsunagiai-mcp` だけです。リーダーにだけ、環境（この Mac と Orca に保存した接続先）ごとのリポジトリを読む `formation_environments`、リポジトリの worktree の一覧を読む `formation_worktrees`、フォルダの中を読む `formation_files`、ファイルの中身を読む `formation_read`、git の状態とブランチを読む `formation_git`、チームメイトを予定に入れる `formation_plan`、チームメイトを起動する `formation_launch`、チームメイトのターミナルだけを止める `formation_stop`、チームメイトを終える `formation_close`、チームメイトの判断ページを調べてアプリに渡す `formation_page`、起動したチームメイトの様子（Orca の待ちの状態と、ターミナルの末尾）を読む `formation_status` を渡します。ほかに渡すのは読み取りのツール（`list_inbox`、`get_thread`、`list_events`、`db_profiles`）だけで、書き込みのツール（`archive`、`set_read`、`trash`、`db_profile_save`、`db_test`）と、言語サーバーのツール（`lsp_settings`、`lsp_server_save`、`lsp_server_delete`、`lsp_repo_ssh_host_set`）は渡しません。
- `formation_launch` には環境、リポジトリ、チームメイトの名前、最初の指示を、`formation_plan` には環境とリポジトリを渡します。環境は、リーダーが動いている PC の `local` だけです。ほかの環境は、何も作らずに断ります（SendMessage が同じ PC の中でしか届かないためです）。ブランチ、ブランチの起点（`base`）、フォルダは、渡しても渡さなくてもかまいません。その環境に無いリポジトリは断り、候補を返します。
- リーダーは、チームメイトを起動すると、Claude Code の `CronCreate` で 10 分ごとの見回りを登録し、`formation_status` でその様子を読みます。権限の確認で止まっている、知らせのないまま待っている、エラーで止まっている、のどれかなら、あなたに日本語で一行知らせ、作業中なら何も言いません。チームメイトが終わるか閉じると、`CronDelete` で見回りを消します。`formation_status` は読むだけで、チームメイトには何も送りません。ターミナルの末尾は、資料として囲んで渡します。
- `formation_worktrees`、`formation_files`、`formation_read`、`formation_git` は読むだけです。読めるフォルダは、リポジトリの本体のフォルダ（`folder` を省いたとき）と、`formation_worktrees` に出る worktree だけで、そのほかのフォルダと、フォルダの外を指すパス（絶対パスと `..`）は断ります。ファイルは 384 KiB まで、UTF-8 のテキストだけ読み、答えは 2,000 行までで、続きは行の位置（`offset`）を渡して読みます。`.git` の中と、`.env` で始まる名前のファイルは、一覧に出さず、読むことも断ります。
- ブランチは、渡さなければ Orca が決めます。渡すときは、git が受け付ける名前なら形は問いません（`-` で始まる名前などは断ります）。worktree は Orca に頼んで作り、この Mac でも保存した接続先でも、そのリポジトリのブランチを見て決めます。ローカルにあるブランチはそのまま開き、`origin` にだけあるブランチ（前のチームメイトが push して閉じたブランチ）は `origin/{ブランチ}` から同じ名前で切り、どこにも無い名前は新しいブランチとして `base`（渡さなければ `origin/HEAD`）から切ります。別の名前で作ることはなく、別の worktree が開いているブランチや使われている名前は、Orca の言葉を返して断ります。`base` は新しいブランチにだけ使え、あるブランチ、ブランチなし、フォルダと一緒の指定は断ります。
- フォルダを渡すと、worktree は作らず、そのフォルダでチームメイトを動かします。フォルダは、そのリポジトリの本体のフォルダか、Orca が一覧に出す worktree の絶対パスです。一覧に無いフォルダ、別のリポジトリのフォルダ、ブランチと一緒の指定は断ります。
- `formation_launch` は、その PC の Orca で、指定したリポジトリの `.claude/worktrees/` の下に新しい worktree を作り、そのターミナルで `claude -n {チームメイトの名前}` を auto モード、effort medium で、`--plugin-dir` に `feature-dev` のプラグインを付けて起動して、最初の指示を送ります。リーダーは、その名前に SendMessage で指示します。
- `feature-dev` のプラグイン（工程ごとの手順書と 7 つの agent）は、アプリに入っていて、チームメイトを起動するときに、その PC の設定フォルダの `formation-plugin/` に、全体で書き出します。中身が同じなら書き直さず、書けなければ何も作りません。
- `agent` に `codex` を渡すと、チームメイトは Claude Code の代わりに `codex --sandbox workspace-write --ask-for-approval never` で動きます（プラグインは付けず、書き出しもしません。`formation_plan` にも `agent` を渡せます）。SendMessage は Codex に届かないので、リーダーはチームメイトに、結果を書くファイルの絶対パスと、最後に置く空の `{そのパス}.done` を指示し、そのファイルがディスクにできるのを待って、結果を読み、頼んだチームメイトに渡します。
- `formation_page` には、チームメイトの名前と、判断ページのファイルの絶対パスを渡します。起動済みのチームメイトだけを受け付け、ページの形、ファイルの場所（リポジトリとその worktree の中だけ。`.git` と `.env` で始まる名前は読みません）、日本語の文が `yomiyasu` の推敲の記録にあることを調べ、通ったものだけを、フォーメーションの `pages.json` に記録します。通らないときは、理由を 1 行ずつ返し、何も記録しません。リーダーは、その理由をそのままチームメイトに返して、直させます。
- リーダーは、`feature-dev` を始めるとき、最初のチームメイトの前に `claude plugin list` で `yomiyasu` と `natural-japanese` が入っているかを確かめ、無いものを、ユーザーのスコープに `claude plugin marketplace add` と `claude plugin install` で入れます。`yomiyasu` を入れられないときは、判断ページが通らないので、理由を伝えて止まります。`natural-japanese` を入れられないときは、それ無しで進めます。
- `formation_close` は、チームメイトのターミナルを閉じ、worktree を消します。リーダーが使うのは、あなたがチームメイトを閉じるようはっきり頼んだときだけです。終わったチームメイトは、あなたが画面の × で閉じるまで、worktree とともに残ります。ブランチも、つなぎAI が作ったものなら消し、そのリポジトリに前からあったブランチは消しません。フォルダを渡して起動したチームメイトが中で動いている worktree は、そのチームメイトを先に閉じるまで消しません。コミットしていない変更、追跡していないファイル、どのリモートにも無いコミットがあるときは、何も消さずに理由を返します。強制して消すことはありません（強制の削除は、画面からあなたが押したときだけです）。フォルダを渡して起動したチームメイトは、ターミナルを閉じて記録から外すだけで、フォルダも worktree もブランチも消しません。
- `formation_stop` は、チームメイトのターミナルだけを閉じます。worktree、ブランチ、記録は残り、画面のカードは完了のまま残ります。feature-dev のリーダーは、役割を終えたチームメイト（工程の完了を確かめた、工程をやり直しに戻した、codex のレビューの結果を渡した）を、これで止めます。止められなければ、理由をあなたに伝えて残します。
- 起動したチームメイトと予定のチームメイトは、フォーメーションごとに `formations/{フォーメーションの名前}/children.json` に記録します（Codex のチームメイトには `agent` も記録します）。リーダーのツールが読み書きするのは、自分のフォーメーションの記録だけです。チームメイトへの指示の文は記録しません。保存した接続先のフォーメーションの記録は、その PC にあり、つなぎAI の画面は、その PC のサーバー（[Orca](orca.md#その-pc-のサーバー)）につないで読み、閉じたチームメイトを消します。
- サインインは、下の「Claude の接続方式」で選んだ方式です。書体、配色、キーは Orca のターミナルと同じです。
- リーダーに打ち込んだ内容と、Claude Code が呼んだツールや道具の結果は、Claude Code を通じて Anthropic に送られます。チームメイトへの指示は、Orca が動かすチームメイトの Claude Code を通じて Anthropic に送られます。
- ほかの行を選んでも、開発の画面を離れても、リーダーは動き続けます。戻ると、同じ Claude Code が出ます。Claude Code が自分で終わったときは、次にフォーメーションを出したときに起動し直します。保存した接続先のフォーメーションでも同じで、Claude Code が終わるとその Orca のターミナルも閉じ、次に出したときに新しいターミナルで起動します。
- アプリを終了すると、リーダーの Claude Code も終えます。

## Claude の接続方式

Claude Code を使う機能（メールの AI 要約、Slack のメッセージの要約、Orca に渡す要約と、メール、Slack、Todo、カレンダー、スキルのタブ、データベースの画面の Claude Code のペイン、開発の画面のリーダー）は、Claude のサブスクリプションか、Anthropic の API キーのどちらかで動きます。
設定の Claude タブの 1 枚目のカード「Claude」に、「サブスクリプション」と「API キー」の 2 行があり、ラジオで使う方を選びます。
使っていない方の状態も、それぞれの行に出ます。

- 初めはサブスクリプションです。`claude auth login` でログインしておきます。
- API キーは、Anthropic の Console で、ワークスペースに限定したキーを作って使います。
- 保存したキーが使えるときは、API キーのラジオを押すと切り替わります。キーが未登録のときと、Anthropic に拒否されたキーのときは、切り替えずにキーの欄が出ます。キーを貼って「確認して保存」を押すと、Anthropic に問い合わせて確かめ、使えるときだけ保存します。
- Admin キー（`sk-ant-admin…`）と、`sk-ant-` で始まらない文字列は、保存しません。
- キーは OS の資格情報の保管場所に保存し、画面には出しません。貼った欄は、読んだらすぐ空にします。
- キーに切り替えると、この端末の Claude Code はログアウトされます。サブスクリプションに戻すときは、ターミナルで `claude auth login` を実行します。
- API キーでは、呼び出しごとに課金されます。費用はアプリに出しません。
- 「貼り直す」でキーを入れ替え（方式は変わらず、ログアウトもしません）、接続解除（確認あり）でキーを消します。使っているキーを消すと、方式はサブスクリプションに戻ります。
- キーの状態は「確認済み」「確認できません」「使えません」のどれかです。Anthropic に問い合わせられないときは「確認できません」と出ますが、保存したキーは使い続けます。キーが拒否されたときは使えません。資格情報の保管場所を読めないときも、キーの行だけが「確認できません」になります。

## Claude のモデルと effort

設定の Claude タブの 2 枚目のカード「モデルと effort」に、用途ごとに 2 つずつ選択欄（モデルと effort）があります。
用途は、Slack の要約（Slack のメッセージから Todo を作るとき）、メールの要約（メール詳細の AI 要約）、プロンプトの会話、Slack に貼る文章の校正、Slack のスレッドの相談、Orca に渡す要約（Orca に渡すペインで、渡す内容を要約するとき）、Todo の相談、Slack の相談の 8 つで、それぞれの `claude -p` の呼び出しが、自分の用途の設定を使います。
「プロンプトの会話」「Slack に貼る文章の校正」「Slack のスレッドの相談」「Todo の相談」「Slack の相談」は、Claude Code のペインに替わったので、いまは呼び出しがなく、選んでも何も変わりません（欄は、あとの変更まで設定に残ります）。
`claude` を使えない状態でも、この欄は出ます。
選ぶとすぐ保存し、次の呼び出しから使います。

- モデルは、Haiku・Sonnet（初期値）・Opus から選びます。モデルを変えると、effort がそのモデルの推奨（Haiku は medium、Sonnet は high、Opus は medium）に切り替わります。
- effort は、low・medium（初期値。Slack のスレッドの相談だけ high）・high・xhigh・max から選びます。`--effort` は常に付けて呼びます。選択欄は値で色が変わります（low は灰、medium は緑、high は黄、xhigh は橙、max は赤）。
- 保存した値が一覧にないときや、ファイルを読めないときは、その用途を初期値（Sonnet と medium）に戻します。用途ごとに選べるようになる前の、1 組だけ保存したファイルは、その値を 8 つの用途すべての初めの値にします（Slack のスレッドの相談が保存されていないファイルは、その用途を初期値の Sonnet と high にします）。
- effort が high・xhigh・max のときは、1 回の呼び出しを待つ時間を 300 秒にします。それより低いときは、要約が 60 秒、Orca に渡す要約が 120 秒です。

## Claude との連携

Claude Code から受信トレイと予定と、データベースの画面の接続と、Todoist のタスクと、スキルと、開いている画面の欄（メール、Slack、Todo の画面）を扱う MCP サーバー `tsunagiai-mcp` があります。
設定の手順は [Claude との連携（MCP）](mcp.md) にあります。
